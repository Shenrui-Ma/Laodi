# Laodi Skill 使用说明

## 支持边界

Laodi 读取当前用户有权访问、且解析器明确支持的客户端数据目录。当前版本是否支持已安装的客户端、后台监测是否存活、是否完成初始扫描，都以 CLI 实际返回为准。安装了 Skill 不等于安装或启动了 Guardian。

Windows 当前为待完整验收的开发实现：安装器可为已核对的客户端配置 Hook，并注册后台与通知身份，但安装成功不代表用户已看到通知。未知 Windows 客户端仍返回不支持；不要用 `--build` 将真实客户端伪装成已核查构建，也不要把合成测试结果当成真实工具回调或用户可见通知。客户端工具回调与后台快照是两个独立通道，一个正常不能证明另一个已覆盖。

`--format agent-summary` 的目标是输出受约束的脱敏 JSON：不包含项目名、完整路径、源码、Git 历史、凭据、客户端任意自由文本。不要为了得到更详细的回复绕过这个接口。若所安装版本不支持该格式，说明版本不兼容并依据可信 README 引导升级，不降级为读取原始记录。

## 查询选择

发行包不修改 PATH。macOS 先查 `command -v laodi`，不可用时使用 `"$HOME/Library/Application Support/Laodi-skills/runtime/laodi"`；Windows 先用 `Get-Command laodi.exe`，不可用时使用 `$env:LOCALAPPDATA\Laodi-skills\laodi.exe`。下面的短命令均指已确认的可执行文件。

```sh
laodi status --format agent-summary
laodi check --format agent-summary
laodi incidents --format agent-summary
laodi doctor --format agent-summary
laodi protect status --format agent-summary
```

- `status`：解释后台监测是否运行及其范围。不要把 CLI 能运行等同于守护进程在运行。
- `check`：一次性、只读检查已支持来源；不会启动后台服务。扫描不到支持目录和扫描完成没有线索是不同结果。
- `incidents`：读取已经记录的事件摘要；没有后台服务时，历史为空不代表当前没有问题。
- `doctor`：只读检查版本、支持范围及目录可读性；不修复、不更改权限，也不查询系统通知许可。后台存活看 `status`；通知许可需另查已安装 helper 的 `--status`。
- `protect status`：在支持该功能的平台版本中，只读核对可选归档限制。`unsupported_client`、`degraded`、`unknown`、`recovery_needed` 都不能说成保护有效；最后一种表示应在客户端退出后执行 `protect disable` 恢复。`enabled` 也不是实际阻断或上传次数。

以已安装版本的 `--help` 为准，不补造输出，不把规划当成功。

## 证据含义

| 摘要中的事实 | 可以说 | 不能据此说 |
|---|---|---|
| Git 历史路径出现在支持的快照清单 | 包含历史对象的本地快照线索 | 历史已经上传成功 |
| workspace_snapshot开头的事件 | 其他工作区快照的清单、尝试或接受记录，按具体阶段解释 | 必然含Git历史/秘密、必然未经用户授权 |
| sensitive_tool_access_requested | 工具请求访问某类敏感位置，默认只记录 | 文件内容已读取、密钥已上传 |
| sensitive_tool_output_detected | 支持的工具输出出现疑似凭据；按 source 区分来源 | 密钥有效、已进入模型请求、已经上传成功 |
| hook_coverage_degraded | 部分工具事件未完整检查或存在历史漏检 | 全部工具均安全、全部监测已失效 |
| global-configs出现在附加配置清单 | 配置元数据被列入快照；未读取配置内容 | 配置必然含密钥、秘密已经泄露 |
| 经过验证的状态表示待上传/失败/重试 | 客户端存在上传尝试或待处理记录 | 已成功上传，或失败后不会重试 |
| 经过验证的接受字段与对应清单相关联 | 客户端记录表明上传获确认 | 远端永久留存、用于训练或对外公开 |
| 格式未知、目录不可读、监测停止 | 对应范围未覆盖或已降级 | 当前安全或已经发生泄露 |
| 只观察到归档文件或网络连接 | 存在该本地文件或连接 | 文件内必然有秘密，或连接传了该文件 |

具体事件枚举及语义以实现和版本验证结果为准。用户希望进一步取证时，先保全本地记录并制定针对性步骤，不自动读取所有项目或删除证据。

用户主动要求查看代码、git log或提交摘要，属于任务上下文，不要把这些正常操作直接解释成后台整仓上传。模型自述“未读取秘密”不能代替审计。会话审计不是默认功能；只有用户明确要求时，才在本地提取必要的工具元数据，不能把聊天正文、模型请求头或环境变量值转交给另一个模型。

## 安装与通知

用户说“装老底”或“开启提醒”才进入接入流程：找到可信仓库/已有发行包的说明，确认版本，采用该版本真实提供的命令。官方仓库是 `https://github.com/Shenrui-Ma/Laodi`，具体安装命令以其 README 为准；macOS 已安装版本可用 `laodi update` 更新；Windows 从 beta.3 起可用 `laodi update` 查询专用推荐通道，仍支持 `--version` 固定已发布版本；beta.2 及更早版本首次升级需显式指定新版标签。本地候选包也可重新运行安装命令更新，不编造第三方镜像或版本号。

安装后解释初次检查结果，包括已有清单和接受记录。后台不逐条通知既有基线，不代表没有历史线索。解析器升级后新增分类的首次观察也不能说成刚刚上传；按摘要中的未知项说明发生时间不明。

只要工具正常运行，就无需让 Agent 获得管理员权限。目录不可读时准确说明覆盖缺口，不把 `sudo`、全盘访问或 Agent Full access 当默认修复办法。

macOS 的通知 helper 是无窗口本地程序：请求通知权限为显式操作，查询通知状态为只读操作。拒绝权限后仍可通过 `laodi incidents` 查看已记录事件。不要为了测试“用户能看到”发送通知，除非用户要求或批准通知测试；更不能声称已送达眼前。

通知许可的只读查询路径：

```sh
"$HOME/Library/Application Support/Laodi-skills/runtime/LaodiNotify.app/Contents/MacOS/LaodiNotify" --status
```

若为 `denied`，由用户在系统设置 → 通知 → 老底中开启。不要反复请求权限，也不要将 helper 的 `accepted_by_os` 解释为用户已经看到。

## 处置分工

老底已自动完成本地检测、脱敏记录、提醒与已启用的固定归档目录限制。通知没有“一键阻止”、自动修复或跳转 Agent 的动作；Skill 不会收到系统通知后自行唤醒。

Windows 默认提供工具事件监测，新版还支持针对已核验 3.11.2 旧构建的可选归档限制；先检查安装版本是否提供 `protect`，启用时用 `--app` 指定实际 EXE 并先 dry-run。其他构建不能套用，不自动降级客户端。Windows 真实快照上传检测仍未接通。用户来询问时，Agent 可以先查询脱敏摘要、解释证据阶段，再按明确要求启用或撤销受支持的限制。不要承诺从摘要定位某个具体密钥或文件，摘要有意不包含这些值。若需要更细的本地取证，应单独确定范围，不读取完整日志或秘密原文给模型。

| 提醒类型 | 推荐下一步 |
| --- | --- |
| 疑似凭据输出 | 确认任务用途与是否为合成值；若真实凭据可能已暴露，由用户到服务商撤销或轮换；不要再索取原值 |
| 快照清单或上传尝试 | 查询当前保护状态；支持且用户要求时，等客户端正常退出再启用保护；其他工具需按该产品已核实的设置处理 |
| 客户端上传接受记录 | 保留脱敏事件，区分记录与实际载荷；需要远端处置时由用户向相应服务申请，老底不能删除云端副本 |
| 工具或快照覆盖缺口 | 分别查运行状态、适配器和队列；不自动扩大权限，不把未知当无风险 |
| 归档限制失效 | 查 `protect status`，不能继续承诺有效；`recovery_needed` 需退出客户端后撤销，未知版本不强行启用 |
Windows 使用 `laodi notifications status` 只读查询通知注册与系统 API 状态；不应期待 macOS 式授权弹窗。`enable`、`disable` 显式管理自有接入；`test` 会发送合成通知，只有用户要求或批准测试时才执行。`accepted_by_os` 仅表示 API 接受，勿扰、策略与实际可见性仍须分开解释。`unknown` 与错误码表示系统状态未确认，不能解释为已允许。

部分打包桌面宿主会虚拟化文件或注册表。新版安装器会在核验后尝试转交给同一用户的桌面环境；若转交结果不确定，不重复启动安装，应先检查状态。无法转交时，再在普通 Windows 用户终端运行同一可信安装入口，不关闭隔离或系统防护，也不把应用私有目录中的安装记录误认为普通桌面后台已经接入。

## 回复长度

通常 2–4 句即可：先说实际发现，再说证据边界和监测/通知是否正常。只有用户要求排查或处置时才展开。默认不给无关的安全清单，不借提醒打断用户的长任务。

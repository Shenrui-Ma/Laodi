# 从快照线索扩展到敏感读取与发送观察

日期：2026-09-18。性质：证据核查与路线设计。后续`0.2.0-dev`已实现适配器 A/B工具事件检测，具体接口和验证边界以[工具检测说明](TOOL-HOOKS.md)为准；本文的系统探针与纯内存发送观察仍是未来TODO，尚未启用。

## 一、这三类是否属于本次已证实案例

| 路径 | 本轮公开证据结论 |
|---|---|
| Bash读取`.env`，内容通过工具结果送给模型 | 没找到命令、秘密输出及对应请求三者相互印证的一手材料。Git对象可能保存历史秘密，不等于执行过`cat .env`。 |
| 不留快照的纯内存直传 | 没找到直接证据。`app-memory:global-settings`是extra清单中的采集来源，后续仍可走归档流程。成功后删除`.enc`也不等于未曾落盘。 |
| 其他Agent自己的上传机制 | 本次某APP报告不能证明其他产品的行为。比较、转述和另一事件的链接需独立取证，不能合并计入本次证据。 |

来源核查与本机观察的具体记录保留在本地。公开描述缺少独立原始磁盘或服务端记录时，不应据此断言上传内容、目的或范围。没有找到证据不代表这些路径不可能存在。

环境查询、目录列举及宿主 Git 上下文不能单独证明 `.env` 或真实私钥进入模型请求，也不能把功能测试写成秘密泄漏案例。

## 二、必须区分的事实

未来统一事件模型至少保留以下不同含义，而非一个笼统的“泄露”事件：

| 事件语义 | 证据要求 | 不能推导 |
|---|---|---|
| 请求访问敏感位置 | 工具参数或可解释的命令输入 | 文件实际存在、已读成功、内容已发送 |
| 进程以可读权限打开敏感文件 | 系统文件打开事件及标志、进程身份 | 实际读取了哪些字节、读到了密钥、外传 |
| 工具输出出现疑似秘密 | 在本机检查受支持工具输出的内容结构/模式 | 值一定有效、随后模型请求已包含或已发送 |
| 敏感特征出现在发送前正文 | 合作式发送接口、明确接入的本地网关等可见明文的观测点 | 网络发送完成、服务端保存、其他绕行链路已覆盖 |
| 读取之后出现外连 | 可归属进程的文件事件与网络事件 | 两者必然存在数据因果关系 |

请求构造、发送、HTTP成功和远端留存继续分开。正常构建读取`.env`或Git对象后联网很常见，不可以仅凭时间接近就显示“已上传密钥”。

## 三、优先做工具事件观察：可保持轻量

适配器 A 对应的官方协议定义了工具执行前后事件，执行后有结构化`tool_response`。`command`执行器支持异步；`process`执行器只支持同步。配置按会话加载，项目级hooks不执行。文档同时明确执行后hook不能替换工具输出。这提供了低干扰观察入口，**不是发送前脱敏保证**。

工具事件枚举及配置 schema 需按客户端构建核对，全部运行时字段和异步生命周期须分别验证，不能仅依据静态协议就宣称端到端支持。

设计采用两段判断：

1. 根据Read等结构化路径、Bash输入等记录“敏感访问请求”。简单命令可以识别，任意脚本、变量、别名和间接读取不能靠字符串匹配完整还原。`ls ~/.ssh`与读取私钥要分开，`env`也不等于输出一定含秘密。
2. 对授权接入的工具输出在本机做有界检测。可以识别私钥块、部分格式明确的令牌等；通用高熵字符串只能作为低置信线索。值是否有效不通过外网验证。预期只保存规则ID、类别、时间、应用与会话的本地不透明标识，不保存原始输出、秘密片段或可逆编码。

这会扩展当前“只读快照元数据”的隐私边界：本地检测器短暂接触工具输出，必须在接入说明中明确。不得为了检查秘密再把输出发给模型，不复制完整会话到事件库，也不把原始内容放进argv、stderr、通知或临时文件。

实现仍复用Go核心：薄hook调用本地二进制，结果进入现有事件队列与通知；不需要新常驻Node/Python或另一个模型。使用异步不代表零开销：每次回调进程、输出序列化、积压及退出取消都需测试。超限/丢事件必须显示覆盖不足，不能静默截断后报告安全。不能用无界异步子进程风暴换取表面“不阻塞”。

默认只发送普通系统通知，不注入`additionalContext`，不返回allow/deny、不改命令或结果，不重启现有会话。已有长任务等自然结束后，新会话才启用新增适配。老底异常不阻断开发，这是可用性选择，同时意味着不能保证事前阻断。

反馈示例：

> 老底：工具输出出现疑似凭据。已在本机记录风险，通知不包含具体内容；是否已进入远端模型请求尚未确认。任务继续运行。

## 四、纯内存直传：必须靠发送链路或系统层补信息

只看本地文件变化无法识别没有落盘的数据。常规HTTPS连接的应用、目的地、时间和流量，即使可观察，也不足以判断其中是否包含秘密。[Apple DTS说明](https://developer.apple.com/forums/thread/798872)指出普通内容过滤器看到的是HTTPS加密流；TLS检查仍不能自动解开应用自己额外加密的载荷。

两种不同目标：

- **发现可疑关联**：可选系统文件访问事件＋网络流事件，记录“敏感文件打开后出现外连”。这是风险线索；未知载荷不可标成确认泄露。进程原本已有内存内容或继承的环境变量时，可能连新的文件打开事件都没有。
- **确认发送正文包含敏感特征**：优先使用客户端合作式发送前接口，或用户明确接入、支持对应协议的本地模型网关。仅覆盖经过该接口的请求；后台独立上传、代理绕行、证书固定、压缩/编码和应用层加密需分别验收，不能宣称通用覆盖。

通用TLS中间人会涉及证书信任、协议兼容、代理与连接故障；不适合作为默认安装路线。没有正文观测点就应保留“内容未知”，不要靠“大流量”制造确定性的泄漏结论。

macOS26的URL Filter也不是现成监听器。[Apple WWDC25](https://developer.apple.com/videos/play/wwdc2025/234/)说明它自动覆盖Apple网络API，其他栈需主动参与，实际URL不交给过滤器应用查看。不能未经验证就说它覆盖Electron/Node，更不能将URL判决等同HTTPS正文审计。

## 五、其他Agent：薄适配器共享同一套检测

按产品/版本建立能力矩阵：工具输入、工具输出、模型请求观测、宿主后台证据各自标注支持或未知。安装Skill本身不等于这些通路都被覆盖。

分别接入适配器 A/B 所对应的工具事件协议。它有工具事件与异步回调，但字段、超时、会话结束处理都必须独立适配和验证；不能把一个产品的hook JSON复制过去就宣布支持。没有hook时，才评估只读日志/数据库增量游标：这是事后观测，可能漏掉未落盘、被轮换或截断的输出。

未来代码边界可以保持很小：

```text
已有快照适配器 / 各产品工具事件适配器
                  ↓
          统一事件分类与脱敏
                  ↓
        现有去重、存储、系统通知

可选系统探针另包提供，不作为核心安装前提
```

跨产品的系统探针可以使用macOS Endpoint Security通知事件。官方[OPEN事件](https://developer.apple.com/documentation/endpointsecurity/es_event_open_t)描述文件打开而非内容读取；[客户端初始化](https://developer.apple.com/documentation/endpointsecurity/es_new_client(_:_:))和[entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.endpoint-security.client)有独立权限与发行要求。只订阅通知可避免文件操作进入本工具的授权决策，但仍需要系统层授权，不能沿用Agent已有Full access冒充授权。

FSEvents关注文件系统修改，不能替代读取审计，见[Apple指南](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/Introduction/Introduction.html)。`lsof`、进程/连接轮询等快照也可能漏掉短暂访问，适合调试，不作为完整读审计承诺。

## 六、推荐顺序与验收

1. **下一小版本先试某APP异步工具事件。** 合成`.env`、假私钥、正常高熵数据、仅列目录、错误/被拒工具、超大/截断输出、并发工具、hook故障与会话结束。判据是正确分层、无秘密持久化、无模型注入、无任务中断，并测量新增延迟及内存，不能沿用当前快照版资源数字。
2. **补第二个产品的适配器。** 重放同一批语义测试并增加其真实协议差异；能力矩阵明确每条通路，不宣称“支持该产品全部行为”。
3. **系统只读探针作为独立可选增强。** 待Apple资格、授权和分发路径可验证后再做；覆盖宿主/子进程的文件打开，仍不能确认读取内容。
4. **发送前正文观察单独试验。** 使用回环本地接收器、随机假秘密，证明经过接口的请求可检测；对旁路和加密案例明确应返回未知。系统流量关联不冒充正文证据。

所有默认反馈沿用系统通知＋本地事件，升级证据强度可以再提醒。未来若增加拒绝/脱敏模式，需单独证明对任务的影响，不能把“至少发现”悄悄变成自动拒绝或改写。

当前结论：第一类可通过合作式工具事件显著扩展；第三类可逐产品复用；第二类能增加线索，但在不增加权限、不接入明文发送路径且不改变客户端的条件下，不能保证识别任意纯内存秘密外传。

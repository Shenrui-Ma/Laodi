# Laodi 验证矩阵与发布门槛

> 当前V1按[PRODUCT-V1.md](PRODUCT-V1.md)第8–9节验收不打断Git/长任务的监测模式。本文件的launcher/系统阻断矩阵继续用于研究，不能作为V1默认启用理由，也不能把普通监测叫成已通过阻断验收。

状态：测试规格，未执行完整产品测试。对应 [架构设计](ARCHITECTURE.md)。

## 1. 什么算证明

每条结论必须包含：产品版本、后端版本、OS 版本、应用版本、策略 revision、实际覆盖主体、测试输入、观察结果和已知缺口。

分开记录：

1. **静态依据**：官方 API 或源代码说明。
2. **行为探针**：OS 或 runtime 在合成样本中的行为。
3. **端到端结果**：测试客户端实际不能取得受限内容，测试接收端没有收到合成敏感标记。
4. **真实客户端兼容性**：明确版本的工具可以完成代表性任务，且后台/辅助进程没有脱离声明边界。

前两项不能冒充后两项。没有收到网络标记也不能单独证明被阻断：还要有正向对照证明 uploader 和接收端原本正常、普通允许内容确实到达。

## 2. 测试环境

使用完全合成的项目、历史和无效凭据，例如随机生成 `LAODI_TEST_SECRET_<nonce>`。禁止使用真实公司仓库、用户登录 token 或个人配置做上传实验。

测试接收端仅用于测试，运行在隔离 VM/受控测试网络；不要求普通用户连接任何外部服务做安装自检。完整 egress 测试需控制 DNS、IP、代理与接收端日志；禁止向任意第三方发送标记或利用公开服务规避规则。

准备以下 fixtures：

- 普通仓库、linked worktree、submodule、separate git-dir、对象 alternates。
- 一个仅出现在旧 commit、当前已删除的合成秘密。
- 一个当前允许发送的公开样本文件。
- 敏感配置的公开证书/假密钥/普通同名文件，避免把文件名匹配当有效密钥鉴定。
- 某APP manifest/state 的合成正常、pending、失败、accepted、损坏、超限和未知版本样本。
- 可落盘归档、内存压缩、先加密再上传三种 fake-client 行为。

## 3. Preview：观察器与告警

| ID | 输入/场景 | 验收结果 |
|---|---|---|
| O01 | manifest 包含 `.git/objects` | 事件为清单命中；不说已上传 |
| O02 | 只有 `.enc` 新文件 | 只报告文件变化；内容和上传状态未知 |
| O03 | pending/失败计数增长 | 按已验证版本语义记录尝试；不换算成功次数或流量 |
| O04 | accepted 字段 | 只有字段写入语义已验证时输出客户端接受记录；不推断留存 |
| O05 | 安装前已有证据 | `baseline_existing=true`，不是新发生警报 |
| O06 | 应用版本未知/字段变更 | 语义解析降级；不能沿用“完整兼容” |
| O07 | JSON 截断后续继续写入 | 有界重试，保留部分检查状态，不崩溃不误报无风险 |
| O08 | 大 manifest/路径超长/递归结构 | 限制资源并报告 partial，不读取无限内存 |
| O09 | 清单带外部绝对路径、symlink | 不跟随读取真实目标，不执行路径中的命令 |
| O10 | watcher 丢事件/目录替换/重命名 | 进入 degraded，有界重扫并记录时间缺口 |
| O11 | 目录权限撤销 | 显示不可读取，通知不再声称正常覆盖 |
| O12 | 一份快照反复重试一百次 | 合并同事件；重要证据升级另行提醒 |
| O13 | 通知权限关闭/勿扰/用户未登录 | 记录可测的送达状态与限制，不把 API 成功当用户阅读 |
| O14 | 日志含 ANSI、HTML、恶意通知动作 | 字段转义，无命令/链接注入 |
| O15 | 事件容量达到上限 | 有界增长，关键摘要保留，丢弃计数可见 |
| O16 | Guardian 被结束后重启 | 恢复游标，旧事件去重，覆盖中断时间可见 |
| O17 | 完全无落盘的内存上传 | 测试明确记录观察器漏检边界，不能误报“未上传” |
| O18 | 向关联器注入合成的读取与外联事件 | 只输出相关性，不定性特定文件已传输；这不证明 Preview watcher 能采集这两类事实 |

Preview 发布必须 O01–O18 通过，并且界面标为“已知证据观察”；O17 通过指正确呈现能力缺口，不是实现了检测。

## 4. Launcher：保护整个客户端进程树

| ID | 场景 | 验收结果 |
|---|---|---|
| L01 | 客户端直接读受保护 Git 文件 | 内容不可取得；有可核实拒绝结果 |
| L02 | Python/Node/原生代码读同文件 | 同样受限，不只拦 shell 命令字符串 |
| L03 | 客户端派生子进程读历史 | 继承限制 |
| L04 | `git show` / `cat-file` / 路径别名 | 无可执行文件白名单绕过 |
| L05 | worktree/common-dir/submodule/alternates | 所有被声明保护的真实根均受限；不支持时拒绝完整保护状态 |
| L06 | 敏感路径 symlink、大小写、规范化绕过 | 在支持平台中不能绕过；结果记录实际语义 |
| L07 | 当前源码读写和简单测试 | 允许，原目录无需复制和 Apply |
| L08 | 任意 inherited GIT_*、额外 FD | 不重新指向未保护对象库；最小环境方案经过测试 |
| L09 | Docker socket/外部 MCP/本地代读服务 | 默认不可借其取得敏感内容；开放时明确扩大的边界 |
| L10 | backend 初始化失败/缺依赖 | 不启动无保护客户端 |
| L11 | GUI 已有未受限实例 | 不能只凭新 launcher 退出就报告受保护 |
| L12 | 子进程脱离父进程、daemonize | OS 约束仍成立或该客户端不进入支持清单 |
| L13 | 同 UID 尝试改 Guardian 策略/关掉限制 | 受保护进程无法经开放控制面降低规则；非保护进程威胁另记 |
| L14 | backend 版本升级 | 必须重跑探针与兼容矩阵才能恢复 verified 标记 |
| L15 | 当前源码被正常模型请求发送 | 明确允许内容的正向对照；不声称零源码上传 |
| L16 | 敏感内容此前已经被复制到允许文件 | 测试揭示路径保护边界；不虚构全内容 DLP |

先选择一个 CLI 客户端完成矩阵，再增加第二个。兼容清单记录精确版本组合，不用“理论支持任意命令”替代测试。

## 5. 出站控制

| ID | 场景 | 验收结果 |
|---|---|---|
| N01 | 允许的模型目标 | 正常连接可完成 |
| N02 | 未批准对象存储目标 | 在受控主体范围内阻断 |
| N03 | 同域名模型接口与额外上传接口 | 仅域名控制模式明确无法区分；不报告正文已审计 |
| N04 | 重定向至未批准目标 | 新目标不能继承前一目标的允许 |
| N05 | IP literal、DNS变化、直连 | 与策略约定一致，不能通过简单域名字符串检查绕过 |
| N06 | QUIC/UDP、WebSocket、SOCKS、代理 | 每种协议明确阻断/支持/缺口，没有静默未测放行 |
| N07 | 修改 HTTP_PROXY/绕过代理 | OS egress 规则仍生效 |
| N08 | 断网处置时已有长连接 | 实测中断与否并如实报告；不把新连接阻断当全部断网 |
| N09 | 离线锁 | 受控应用的测试出站均失败，本地功能仍可测试 |
| N10 | 新目标授权超时 | 支持同步规则的后端拒绝，不无提示放行 |
| N11 | TLS/应用内加密上传 | 连接观察不声称知道正文，敏感源预防另行验证 |
| N12 | 收紧规则后旧允许缓存 | 缓存失效，新的决策符合新 revision |
| N13 | 无 remoteHostname 的 socket/CDN共享IP | 不能假冒域名判定；严格策略拒绝或走明确的端点例外 |

任何“防 Git 历史外传”的演示都至少包含 L01–L05、L09 与 N01/N02/N07/N11；不能只测 `cat .git/HEAD`。

## 6. macOS 系统组件

| ID | 场景 | 验收结果 |
|---|---|---|
| M01 | 正常 macOS、安全保护开启 | 已签名、公证组件完成官方安装授权；不要求关闭 SIP |
| M02 | entitlement 尚未获批 | 正式系统防护版本不可发布；Preview 不冒充 |
| M03 | Dock/Finder 启动登记应用 | 系统模式按可核实主体生效，无每次 launcher 要求 |
| M04 | helper/fork/exec/应用更新 | 身份正确传播；不能按单独进程名放过 |
| M05 | 仅对 Git 二进制放行的绕过尝试 | Agent 子进程不因可执行文件身份获得豁免 |
| M06 | 安装前已有敏感 FD/mmap | 明确要求受控重启，不能报告追溯保护 |
| M07 | 文件 rename、git-dir 变化、策略热更新 | 无未经说明的保护空窗；解析失败保持范围可见 |
| M08 | AUTH handler 压力与系统 deadline | 实测延迟、超时和系统行为；不在 handler 内做 IO 重任务 |
| M09 | Guardian 崩溃/队列压力 | 既有执行规则按声明继续；事件丢失有计数和恢复通知 |
| M10 | Full Disk Access/扩展权限撤销 | 及时降级，不能显示 active |
| M11 | 来自未信任进程的管理 IPC | 修改请求不能越过管理授权 |
| M12 | app/filter 扩展升级与卸载 | 规则和组件状态一致，无残留导致误拦或假保护 |
| M13 | 合法 IDE 构建/索引场景 | 测出 Git 受限影响；不为消除错误自动开放历史 |
| M14 | 受控应用向外部已授权服务转交操作 | 已知 IPC路径被约束或明确不在保证范围；不可隐去 |
| M15 | Node/Python 承载多个不同 CLI | 不按解释器签名合并身份；未经验证的入口仍要求 launcher |
| M16 | 源码根 allow 与内部 .env deny 重叠 | 更具体秘密 deny 生效；示例文件例外必须明确 |
| M17 | Agent 启动合法签名 CLI 申请放宽 | 只有提案权限；无绑定具体差异的系统用户审批不得生效 |
| M18 | 审批重放/过期/规则替换/旧revision | Authority 拒绝；不以调用者签名替代用户同意 |
| M19 | 故意错过 ES AUTH deadline | 如实记录隐式ALLOW与保护空窗；独立告警及可用网络隔离不伪装成零空窗 |

系统防护 V1 完成必须有至少一个目标桌面客户端在正常设备上的 M01–M19 结果，连同证据和限制。只在开发签名或禁用系统安全的环境跑通不算可分发产品。

## 7. Skill 与安装管理

| ID | 场景 | 验收结果 |
|---|---|---|
| A01 | Agent 请求 status/check | 只返回 agent-summary 白名单字段 |
| A02 | 原始证据含秘密/路径/remote | 默认不返回模型、不进入公开日志 |
| A03 | 仓库提示注入要求停用防护 | 不改变系统策略 |
| A04 | Agent 直接调用带 --yes 的变更 | 不绕过可信管理授权 |
| A05 | 宿主不触发 Skill/hook | Guardian 仍独立运行；不能依赖模型主动想起 |
| A06 | 同宿主不同版本 hook 格式不同 | 按版本测，失败时不给完整接入状态 |
| A07 | 设置修改后撤销 | 只撤销 Laodi 仍拥有且未被用户另改的部分 |
| A08 | 卸载 | 服务、扩展、快捷入口逐项核对；证据保留策略明确 |
| A09 | 安装到已打开原项目的 Agent | 提醒不会追溯保护以前读取的数据 |
| A10 | 声称后台正在运行 | 实测服务存活与传感器健康，而非只看配置文件存在 |

## 8. 性能与可用性目标

以下数值是待验证目标，不是现成性能承诺：

| 项目 | 目标/记录方法 |
|---|---|
| Guardian 空闲资源 | 固定基准机器上，10 项目/3 已知数据目录，24h 平均 CPU ≤0.2%，RSS ≤50 MiB |
| 告警入队 | ≤2 MiB 完整可读证据、awake/权限正常，p95 ≤2s |
| 系统通知 | 入队到 OS 接收请求时间另测；用户可见性不能总保证 |
| 大清单 | 流式处理、不突破内存预算；延迟单列，不沿用 2s 指标 |
| 数据盘 | 默认日志≤50 MiB，轮转/丢弃/关键摘要策略均有测试 |
| 后端控制 | 单独测 native extension/runtime 的资源，不计入上述数字后声称全产品达到 |
| 系统授权热路径 | S0 spike 得出基线并锁定回归阈值，必须远低于系统 deadline |
| 普通用户首用 | 5位目标用户至少4位无需开发者介入完成接入与测试通知；这是验证计划，不是现有结果 |
| 护栏理解 | 用户能复述“当前代码允许发送、历史受限、何处只是监测” |

负面性能测试包含：依赖目录几十万文件、频繁 rename、快照写入风暴、应用不断重试、磁盘满、事件队列满、系统休眠、通知权限变化。

## 9. 发布证据包

每次发布附带机器可读 compatibility 清单和简短验证报告：

```text
版本与二进制校验和
OS / 客户端 / 后端的具体版本
组件授权前提
通过的测试 ID
失败、跳过和未覆盖测试
从同一套合成 fixture 得到的事件与拒绝记录
性能样本与测量范围
已知限制与回滚方式
```

不得把“用户没报告问题”作为安全验证。真实客户端测试没有证明其恶意动机，只验证 Laodi 在声明边界内的行为。

# Laodi 产品与仓库架构

> 范围修订：本文件保留0.3系统防护研究路线。用户最新要求与S0实测后的当前V1以[PRODUCT-V1.md](PRODUCT-V1.md)为准：不默认拦截、不影响Git/长任务、无专用GUI、普通用户级监测。本文的系统扩展与严格启动器不再是首发前提。

版本：0.3 · 全新路线 · 2026-09-18
状态：待实现、待验证；命令、结构和界面均为规格。
替代范围：替代 Git-Laodi 0.2 的一次性副本管理器主线。保留本地处理、确定性检查和诚实证据原则，不延续 B/W/R/Apply 产品闭环。

研究边界：S0 探针与具体结果保留在本地，不代表本文整套产品能力已经实现。完整 `.git` 拒绝策略可能损失普通 Git 功能；硬链接、既有 FD、预载环境与外部代读服务不能仅靠路径拒绝解决。正式系统扩展仍需单独授权和验证。

## 1. 决策与最新需求

项目名固定为 **Laodi（老底-skills）**；二进制拟名 `laodi`；主要 Skill 拟名 `laodi`。

最新需求优先级：

1. 尽可能阻止未经授权的源码、Git 历史和敏感配置外传。
2. 无法事先阻断的可观测行为，要及时发现并告知，且说明证据强度。
3. 一次安装与必要授权后尽量少操作，在原开发目录继续工作。
4. 足够轻量、容易安装、方便现有 Agent 调用。
5. 以可验证的隐私风险处置为定位，长期价值不依赖某个厂商。

据此选择：**本地隐私守护程序＋平台执行限制＋Agent Skill 入口**。

不再要求用户逐任务复制仓库、Review、Apply；不把迁移 `.git`、提示词约束或目录改名当成防外传机制。

### 1.1 必须先定义“防止上传”

云端 AI 编程通常需要发送用户批准的代码上下文。目标是阻止超出授权的数据流，不是同时允许云端处理源码又声称没有任何源码离机。

默认受保护数据：登记项目的真实 Git 管理数据、用户明确指定的秘密文件和目录，以及经策略确认的非任务资料。默认可以处理的数据：登记项目中允许 AI 使用的当前文件。

**“授权当前代码”仍然意味着客户端可能发送较多当前代码。** 在不检查请求明文、不了解任务意图的情况下，系统不能可靠区分“必要片段”与“过量当前源码”。主路线先控制可读取的数据来源和可建立的连接；请求体级最小化是另一项能力。

用户要求任何字节都不出网时，提供明确的**离线锁**：受控应用禁止外联，仅适合本地推理或离线工作；不能一边使用云模型一边暗示此模式成立。

### 1.2 对“最差及时告知”的准确承诺

对已支持的传感器、应用版本和事件类型建立延迟目标；对不可见的路径显示缺口。没有一个轻量、无特权程序能保证发现任意应用的所有内存直传或加密上传。

完整目标是：**预防范围尽可能广；已覆盖的异常有延迟验收；监测失效主动告知。** 不允许用“所有上传至少都会通知”替代实际覆盖证据。

## 2. 第一印象与传播

主口号：**代码让 AI 写，老底别悄悄带走。**

一句话说明：**在本机给 AI 编程工具划定数据边界，能拦的先拦，有异常及时告诉你。**

首页只突出三个价值：

- 历史、密钥等受保护资料不应被顺手打包。
- 原目录开发，无额外文件搬运与结果合并。
- 异常给出本地证据，正常时保持安静。

传播画面用合成仓库展示：当前文件正常编辑；同进程读取旧历史遭拒；模拟上传端收到允许的内容但没有收到历史标记；通知准确解释哪一步被拒绝。不得把模拟测试冒充某厂商真实行为。

初版无需分享卡生成器、复杂风险评分或“保护了多少亿元代码”的计数器。基本状态与一条可信警报已经提供记忆点。

具体事件来源和观察记录保留在本地，区分事实与未知。首页不以持续指控厂商为卖点，也不使用未经证实的训练、留存结论。

## 3. 交付形态与完成标准

| 交付形态 | 可做什么 | 做不到什么 | 发布判定 |
|---|---|---|---|
| Preview：本地观察 | 检查已知快照/manifest/state、持续事件监测、通知 | 不能看见所有文件读取与无落盘上传 | 仅发布“已知风险监测” |
| CLI Guard Beta | 在原项目启动整个客户端进程树，限制敏感路径和出站目标 | 不自动约束已在边界外运行的桌面实例 | 逐 OS、客户端、版本验收 |
| macOS System Guard V1 | 通过系统扩展控制登记应用的文件访问与连接，覆盖已验证的普通启动方式 | 不自动理解加密请求体、不能追回历史上传 | 本文声明覆盖范围内的首个平台正式交付 |

三者共用事件、策略和通知，不是三个独立产品；安装程序根据本机能力显示可用组件。

**macOS System Guard 是正式产品方向，不是无限期“有空再做”的附加项。** Apple entitlement、签名和系统扩展安装是前置立项风险，应第一天验证。若无法取得所需能力，只能继续发布边界清楚的 Preview/Beta，不能把它们改名为全面防护版。

平台策略：macOS 优先完成系统级路线；Linux 先交付受限启动与已知证据监测；Windows 先研究并验证，不能因依赖项目声称支持就直接声明 Laodi 支持。实际支持以版本化能力清单与 CI/人工验收为准。

## 4. 用户体验：一次接入，持续运行

### 4.1 首次安装

安装器完成以下最小闭环，目标不超过四个用户决策页面：

1. **选择应用与项目**：识别候选应用，仅登记用户选择的 AI 工具；项目允许由用户选择开发目录或明确添加，不全盘读取所有仓库。
2. **展示策略**：说明禁止访问哪些数据、允许哪些模型目标，以及可能受影响的 Git/IDE 功能。
3. **授予必要能力**：系统通知、后台启动；系统防护组件另行走 macOS 官方授权。安装 Skill 不等于完成这些授权。
4. **自检并展示覆盖**：运行合成拒绝探针、监测探针与测试通知。任何一步缺失都显式显示，不做默认绿色成功。

首轮检查将既有快照标成“安装前已存在”，不会说“刚刚泄露”。只报告必要的本地摘要，不默认复制或展示用户源码。

### 4.2 日常使用

- 系统防护已启用且身份可稳定识别的原生/签名桌面应用可按习惯从 Dock/终端启动。
- Node/Python 等解释器承载的 CLI 不能仅凭解释器签名区分。正式默认仍通过 launcher 登记运行实例；只有能可靠绑定脚本入口、实例与后代且通过测试的组合，才允许免 launcher。不能把所有 `node` 或 `python` 进程一起归为同一个 AI 客户端。
- 只有 launcher 能力时，用户使用 `laodi run -- <client>`，或者选择安装单独命名的受保护启动快捷方式。不得悄悄覆盖原始客户端二进制或系统命令。
- 默认不要求每次确认同一批稳定策略；新模型服务、敏感目录访问例外、能力失效等才提示。
- 普通当前文件读写和测试留在原目录，不新增副本同步系统。
- 任务没有异常时不弹“安全成功”通知、不发送周期性日报。

### 4.3 状态面板

拟定输出，表示能力事实而非单一安全等级：

```text
老底正在运行

已登记应用          2
已登记项目          3
敏感文件读取控制    生效（macOS 系统组件）
出站连接规则        生效（本后端已验证的主体/端点范围，不检查 TLS 正文）
某APP 快照线索       兼容性已验证：<实际测试版本>
系统通知            已授权
最近自检            通过，<时间>

已知缺口：允许读取的当前源码可能发送给已批准的模型服务。
```

若只有观察器：明确写“快照监测已启用；读取阻断未启用；连接控制未启用”。服务存活不等于保护已生效。

## 5. 威胁模型

### 5.1 首要防御对象

- AI 客户端、helper、插件或其子进程过量读取原始 Git 历史和本地配置。
- 正常模型调用之外的后台归档、对象存储上传或未知目标连接。
- 升级、进程重启、权限撤销导致原本启用的保护失效。
- 用户误将“已关闭训练”理解成“没有其他数据采集”。

### 5.2 不作绝对保证的情形

- 安装前已经读取进内存、外传或保存在远端的数据。
- root/kernel compromise、用户主动绕过限制、已授权的其他进程代读代传。
- 硬链接/其他副本/共享缓存中未登记的相同内容；路径策略不是全机内容追踪。
- 云端远程工作区、SSH 远端和容器中没有部署相应组件的进程。
- 已批准的当前源码经已允许域名传输；仅凭连接规则无法识别正常上下文与隐蔽外传。
- 无系统访问事件时，进程在内存打包并直传且不留下已知线索。

这些缺口必须成为能力清单的一部分，而不是只存在于长篇免责声明。

### 5.3 信任边界

Skill 和被保护的 Agent 都不是策略管理员。仓库内的配置、README、AGENTS.md、下载内容以及 Agent 生成的命令，都不能自动降低本机保护。

系统执行组件使用最后一个已验证策略；本地守护进程负责解释和记录；用户通过可信管理界面批准敏感例外。CLI 可以发起变更请求，但不能用一个普通 `--yes` 绕过系统防护的管理授权。

系统模式的最终策略由原生受保护的 **PolicyAuthority** 管理职责持有（可位于既有原生组件中，不另造服务平台），存放在普通受控进程不可写的位置。Guardian 只生成提案，无权直接替换生效策略。放宽规则必须走：提交原/目标 revision 与规则差异 → 原生界面显示具体应用、数据范围、目标与时限 → 系统认可的用户授权 → Authority 产生绑定该差异 hash、一次性 request ID、到期时间的审批记录 → 执行组件验证并应用。重放、过期、内容替换和旧 revision 均拒绝。

验证调用者签名只是第一步：Agent 也可以启动合法签名 CLI。因此 CLI 身份本身不赋予放宽权限，不能把“同一用户”“HostApp 曾运行过”或可被同 UID 读取的静态 token 当成用户批准。具体系统授权 API 与控制通道是 S0 必测项；未完成时只允许 Preview 用户级控制，不发布抗绕过的系统管理承诺。

用户级 Preview 无法防御同用户权限恶意进程篡改其全部记录，因此其 hash 只作一致性检查，不称为防篡改证据。系统模式应把策略控制面与受保护应用隔离，并验证 XPC/IPC 调用者身份；不能仅靠 socket 路径保密。

## 6. 总体架构

```text
用户 / Agent Skill / 本地管理界面
                 │ 脱敏查询；管理请求另走授权
                 ▼
          laodi CLI / Controller
                 │ 本地 IPC
                 ▼
      Guardian（一个用户级常驻进程）
       ├─ 应用与项目登记 / 能力健康
       ├─ Evidence：解析、归一、去重、时间关联
       ├─ Policy：确定性决策与版本管理
       ├─ Incident：本地事件存储
       └─ Notify：系统通知 / 安静去重 / 本地详情
                 ▲
       ┌─────────┼──────────────┐
       │         │              │
  已知证据目录   Launcher       macOS System Guard
  watcher/parser OS sandbox      ├─ Endpoint Security 文件授权
  （观察）       （预防）        └─ Network Extension 连接规则
```

**授权拦截热路径不依赖 Guardian 往返，也不调用 LLM。** 原生组件持有有界、预编译策略，及时响应系统；把事件异步交给 Guardian。守护进程忙碌或通知被拒绝，不应让扩展忘记既有规则。

只有一个 Policy 数据模型、一个 Event 数据模型、一个 Incident 状态模型。平台 backend 只是窄接口实现，不建立可执行第三方插件市场。

## 7. 预防：先限制数据源，再限制去向

### 7.1 数据分类

| 数据类别 | 默认处理 | 用户代价 |
|---|---|---|
| 登记仓库真实 Git 管理目录及对象库 | 对登记 AI 应用及受限进程树禁止直接读取，原则上也禁止写入 | Agent 的部分 Git/SCM 功能不能用 |
| 用户明确登记的密钥/私密目录 | 禁读；必要认证材料做单独最小例外 | 某些工具需要额外配置 |
| 被用户明确标为可共享的当前源码 | 允许正常读写 | 可进入批准的云模型请求 |
| 未登记的其他项目 | 严格 launcher 默认不授予；系统模式按可验证的根策略处理 | 跨项目任务需要声明范围 |
| 客户端登录凭据 | 按经过测试的客户端配置最小授权 | 同一进程获得的凭据不能同时保证对它保密 |

默认规则不通过文件名判断“这一定是有效生产密钥”。`.env`、`.pem` 等只是敏感路径候选，最终策略与事件都保留来源与范围。

“用户明确登记”不能变成让用户自己想出所有秘密位置。setup 必须预选并展示内建保护清单：项目内 `.env`/`.env.*`、`.npmrc`/`.pypirc`/`.netrc`、Terraform state，以及用户 `.ssh` 私钥、已知云凭据和 kube 配置路径。依凭据格式/路径选择目录或文件；不把 `.ssh` 公钥、测试证书或 `.env.example` 自动判定为真实秘密，也不无条件自动放行示例文件。用户确认一次后持久生效。

规则优先级是不可覆盖的结构安全边界 → 已获可信审批且有时限的具体例外 → 明确敏感 deny → 一般源码 allow。宽泛的“允许项目目录”不得覆盖其内部更具体的秘密 deny。例外不能由仓库文件或 Skill 自动生成；界面要明确例外期间相关数据可被应用读取。名称规则漏掉的秘密应承认为路径策略缺口，后续内容扫描不能反向夸大首版能力。

### 7.2 Git 路径解析

不能只拒绝 `./.git/objects`。登记时由可信进程解析：工作树根、gitfile、实际 git-dir、common-dir、objects、有限深度的 alternates、submodule 管理目录。处理路径规范化、符号链接、大小写与循环。[S2]

只读 Git 调用使用受控环境，不执行 hooks/filters/fsmonitor，不自动 fetch。无法完整解析时拒绝报告该仓库为完整保护；可保留已知根的保护并显示缺口。

源布局变化、gitfile 指向改变、alternates 新增时重新编译策略。在解析期间把登记应用对相关 Git 管理入口的访问保持为拒绝；若后端不能维持此不变量，该场景不得标为完整覆盖。

### 7.3 Git 兼容性是明确取舍

不允许通过给 `/usr/bin/git` 加全局白名单来恢复功能：Agent 随后就能调用 `git show` 或 `git cat-file` 读取历史。

策略随受限客户端的进程树/可核实的 responsible process 传播；Agent 启动的 Git 不获得豁免。用户在外部可信终端使用 Git 是另一主体，但必须测试边界，不能允许 Agent 经任意 IPC 借用它。

首版不做 Git broker。后续若高频需求证明必要，只考虑明确的有限查询协议；不提供任意 Git 参数、任意 revision 或对象读取 RPC。

文案必须说清：**保持当前代码开发路径，不承诺 Agent 原生 Git 所有能力不受影响。**

### 7.4 出站规则

默认按应用/受限会话维护明确的允许目标；不默认允许所有 `*.aliyuncs.com`、对象存储域或任意 localhost 代理。

新增目标触发一次待授权提示：用户可以拒绝、为本次会话允许，或明确保存规则。不能根据模型一句“测试需要联网”自动永久放行。允许端口、域名、重定向、IP literal、DNS 解析与连接目标的对应关系由后端验证。

域名白名单不检查 TLS 请求体。同一个域名同时提供模型和快照接口时，不能靠域名做到精确区分；状态中明确这一点。首版不默认安装根证书、不全局 TLS MITM、不拦截所有用户浏览器流量。

**原生网络过滤器也不保证知道每条连接的域名。** NE socket flow 的主机名只在系统能提供时可用；直接 BSD socket 等路径可能只有地址和端口。[S11] 因而 backend 必须分别声明 `process_endpoint_control`、`verified_host_control` 能力。不得从一次 DNS 查询、共享 CDN IP 或反向解析就认定后续连接属于允许域名。

Launcher 的域名约束要求唯一受控代理与 OS 禁直连同时成立，并验证 CONNECT/代理身份契约。原生 NE 首先保证主体＋端点控制；可信主机信息缺失时，严格策略拒绝该连接并提示可以配置固定受控代理或申请明确的临时端点例外。无声降为 IP 放行或“网络全开”均不可接受；仅使用端点规则时面板不能显示域名防护生效。

已有连接、WebSocket、QUIC/UDP、DNS、SOCKS、Unix socket、第三方代理及直连绕过全部进入验证矩阵。后端不支持的协议默认拒绝或宣布缺口，不能静默放行。

### 7.5 异常后的处置

- 明确禁止的敏感读取：同步拒绝，异步通知；不能等通知出现再决定是否读取。
- 未授权的新连接：在支持的控制后端中阻断或挂起到有界超时，超时拒绝；只提醒不算预防。
- 只有可疑清单、没有控制后端：及时提醒并提供停止应用/配置防护的操作，不声称已止血。
- 高置信事件可按用户预先授权的策略隔离对应应用外联；禁止仅凭“大文件＋云域名”自动杀进程。
- 隔离接口必须报告“新连接已禁止”和“已有连接是否实际中断”。不支持中断既有连接时不能显示“已彻底断网”。

## 8. 执行后端

### 8.1 Launcher Backend：先获得可测试的预防能力

采用经过固定版本验证的现有 sandbox runtime，优先评估 Anthropic sandbox-runtime；不自行维护一套全新跨平台 sandbox。上游使用本机 OS 机制并可约束整个进程树，但仍标为研究预览，必须锁版本与重测。[S3]

Go 核心只通过明确 argv 与配置契约启动后端。后端若依赖 Node 或系统包，安装界面如实列出；观察器不因此要求 Node。不得把它宣传成“所有能力只有一个零依赖二进制”。

关键要求：

1. 包装客户端主进程，而非仅包装它的 Bash 工具。
2. 启动前完成真实根解析与策略编译；内部探针验证拒绝和允许的行为。
3. 不用 login shell 重新注入未知环境；保留最小必需变量，敏感凭据逐客户端列例外。关闭不必要的继承文件描述符。
4. 限制 Docker socket、任意 IPC、外部 helper 和可代读代传的本地服务。确需开放则标明被扩大的信任边界。
5. 缺依赖、内核机制受限、策略加载失败时不悄悄退回普通启动。
6. 记录 launcher session 与实际进程身份；不能只因子进程退出码为 0 就宣布受保护。

GUI 只在实测通过的组合中开放。已有 Electron 单实例可能接收新启动请求并在旧进程中处理，因此 `open -a` 成功不能证明沙箱生效。[S4] 无法确认进程归属时要求用户关闭旧实例再重新启动；不自动强杀。

### 8.2 macOS System Guard：完整产品的目标平台

原生宿主 App 承担系统扩展安装、通知、状态入口和授权。Endpoint Security extension 执行文件访问授权与进程身份追踪；Network Extension 执行连接规则。保持小型原生界面，不引入 Electron 或网页控制台。

Apple 的 Endpoint Security 能提供同步 AUTH 与异步 NOTIFY；需要 entitlement 与用户授权，不能靠安装 Skill 绕过。[S5] 系统扩展签名、分发、升级、卸载及用户授权是正式工作项。[S6]

文件规则不能仅处理一次 AUTH_OPEN 就宣称所有读取都受控。实现阶段必须研究并测试已打开 FD、mmap、进程 exec/fork、复制、缓存授权、重命名与路径变化的影响；安装之前已打开的敏感句柄通过受控重启收敛。覆盖不全时保持降级状态。

判定主体使用可核实的代码签名、应用身份与运行实例信息。路径/进程名只作展示，不作唯一身份；helper、子进程和更新后的版本都需追踪。扩展的规则缓存必须在策略收紧时失效，禁止沿用此前允许结果。

授权 handler 使用本地有界查表，遵守系统 deadline；事件解析、大文件读取、网络查询和模型调用均不进入 handler。压力下的超时/降级行为要测试和显示，不能暗示系统会自动替项目 fail-closed。

Apple 已明确说明 AUTH 超过 deadline 时会终止 ES 客户端，并对该操作隐式 ALLOW；重启不撤销已发生操作。[S5] 因此这是已知的 fail-open 风险，不是待猜测的行为。独立健康路径必须把文件能力转为 degraded、记录空窗并告警；网络组件仍可用且用户已预授权时尝试隔离相关主体，分别验证新连接与已有连接结果。健康探测及隔离存在延迟，不能保证弥补超时瞬间已放行的读取或外传。

网络扩展可提供连接层控制，但不能仅凭 HTTPS 连接判断正文。[S7] 新 URL 过滤能力也不作为任意客户端自动支持的前提。

### 8.3 既有防火墙配合

LuLu 等工具可作为用户已有的连接控制辅助；未核实稳定公开接口之前只提供可审阅的官方操作说明，不直接修改其内部数据库。[S8] Laodi 不把“安装了防火墙”当成“已检查上传内容”。

### 8.4 某APP 已知机制处置

某APP 是首个**观察器解析器**，不是核心唯一依赖。将客户端版本、数据目录、schema 与已验证字段语义绑定。

锁 checkpoint 目录等办法最多作为实验性、版本限定的缓解动作：先保全记录、确认应用暂停、记录原状态、验证不会转路径/重试风暴，再提供撤销。不默认 `rm -rf`，不竞速删除 `.enc`，不把同用户可解除的文件标志当作恶意进程隔离。

有正式可靠的关闭选项时优先使用；没有可靠办法时只提供证据和可验证的隔离入口，不编造一个“修复成功”。

## 9. 观察与证据

### 9.1 传感器

| 来源 | 能观察到 | 不能据此断言 |
|---|---|---|
| 已知数据目录 watcher | 创建、修改、替换、删除等本地变化 | 谁读取了哪些文件、是否已出网 |
| manifest/state 解析器 | 文件类别与已验证的客户端状态字段 | 云端实际留存、使用和删除情况 |
| sandbox 后端事件 | 能核实的拒绝/连接决策及范围 | 未受限进程的所有活动 |
| Endpoint Security | 系统提供的文件和进程事件 | 单凭读取证明网络发送 |
| Network Extension | 进程关联的连接和控制结果 | TLS 明文内容或某文件一定被上传 |

watcher 不是读取监视器。事件可能合并、遗漏、目录替换或权限失败；必须有受限重扫、重启恢复与可见的健康状态。[S9]

### 9.2 证据类型分开存储

```text
artifact_observed
sensitive_manifest_match
upload_attempt_recorded
upload_acceptance_recorded
file_access_observed
file_access_denied
connection_observed
connection_denied
sensor_degraded
policy_changed
```

事件可建立关联，但不把它们强制升级为单一“泄露”。例如“含历史的清单＋同应用外联”只支持有证据的相关性，不能证明传输正文。

`upload_acceptance_recorded` 要求验证对应客户端版本中字段的写入路径；仅看到 `lastAcceptedManifestHash` 字符串不够。来源是客户端记录时，在界面和机器输出中都保留 `evidence_origin=client_record`。

### 9.3 建立事件时间语义

同时记录 `observed_at`、可选的 `source_reported_at`、`baseline_existing`。本地旧文件的 mtime、客户端时间与实际上传时间不强行等同。

首轮 baseline 与运行后新增事件分开；事件丢失后的重扫发现应标为“恢复后发现，确切发生时间未知”。休眠、用户退出、通知禁用期间无法承诺实时送达。

### 9.4 解析器安全

只读取允许位置的普通文件，限制输入字节、条目数、路径长度和嵌套深度；拒绝跟随不受信 symlink。不解压未知归档、不解密快照、不执行日志中的命令。

不复制 `.enc` 大包。manifest 优先流式解析需要的字段；默认只保存类别计数、局部证据引用与短摘要。字节上限导致检查不完整时记录 `partial`，不得输出“无风险”。

初版解析器只有经过测试的 某APP schema；其他客户端必须提供合成 fixture、版本条件和字段出处后才加入。未知版本可报告“目录出现变化”，但高级语义进入 `unsupported_schema`，不猜字段。

## 10. 通知与情绪价值

默认通知不包含项目名、绝对路径、文件正文或密钥，避免锁屏再次泄露。点击打开本地详情，Agent 只获得脱敏摘要。

示例一：

```text
已阻止一次 Git 历史读取
登记的 AI 应用尝试读取受保护的历史对象，操作已被拒绝。
当前源码仍可用于已批准的模型请求。
[查看本地详情] [管理例外]
```

只有后端提供可靠拒绝结果才能显示“已阻止”；仅拒绝了启动或网络连接时说清阻止的是哪一步。

示例二：

```text
发现包含 Git 历史的本地快照线索
已确认：清单列出了 Git 对象。
未确认：是否完成上传、云端是否仍保留。
来源：匹配版本的客户端本地记录。
[查看证据] [查看处置]
```

示例三：

```text
老底的监测范围发生变化
应用已升级，当前版本的快照格式尚未验证。
系统文件限制仍生效；客户端快照解释暂不可用。
```

去重按应用身份、工作区匿名标识、证据对象及事件类别进行。相同重试在十分钟窗口聚合，证据升级、保护失效或新数据类别仍可即时提醒。通知被系统拒绝要显示“未送达”，本地队列保留；不能把调用通知 API 成功等同用户看到。

不使用风险总分替代事实，不用每次正常联网打扰用户。用户可以静音低优先级摘要；关键保护失效不能被悄悄降为正常。

## 11. 技术选型与轻量预算

核心使用 **Go 单 module、一个 `laodi` 可执行文件**。同一二进制可运行 CLI 与 `daemon`；不另开 HTTP 网页后台。

观察器使用少量事件监听依赖，例如 fsnotify；必须考虑 macOS 后端对 FD 数量的影响，避免给整仓每个文件都挂 watcher。[S10] 性能不能仅凭“事件驱动”推定。

数据采用：原子 JSON 状态＋有界 NDJSON 事件日志＋小型去重/游标文件。首版不引入数据库，不存源码副本、不扫全机历史。并发写由单 Guardian 串行负责；恢复逻辑处理截断记录和 schema 版本。

macOS 系统扩展需要原生组件，这是平台授权能力的成本，不为了“只有一种语言”而规避。Go 负责共用逻辑；原生层只负责 OS 生命周期、同步规则与事件适配。Launcher 后端为可选外部依赖，锁定版本。

建议预算（全部为待测目标）：

- 用户级 Guardian 空闲 RSS ≤ 50 MiB，平均 CPU ≤ 0.2%（固定基准机器、10 个项目、3 个已知数据目录）。
- 已支持的小型证据从完整可读到本地告警入队 p95 ≤ 2 秒；操作系统通知展示延迟单列。
- 空闲不定时递归扫描源码；维护性目录重扫有预算、退避与次数上限。
- 默认事件存储保留 7 天、总量上限 50 MiB；达到上限优先丢可重建低价值事件，并保留丢弃计数。未处理高价值事件保留摘要；容量不足立即告知。
- 原生授权路径延迟目标和总组件资源预算由 S0 spike 建立，不把用户级 Go 进程预算冒充整套系统预算。

轻量优先体现在用户无需复制项目、无需常驻模型、无需云账号、无全盘循环扫描。系统授权不能为了看起来轻而省掉。

## 12. CLI、Skill 与自动化契约

本节命令和客户端标识均为历史设计示意，不是当前 CLI 用法；实际接口以已安装程序的 `--help` 为准。

```text
laodi setup                         # 生成并执行经用户批准的接入计划
laodi status --format agent-summary # 脱敏能力与健康状态
laodi check --client <client-id>          # 有范围的只读检查
laodi incidents --format agent-summary
laodi doctor                       # 自检后端、权限、通知、规则版本
laodi run -- <client> [args...]      # 原目录受限启动
laodi protect request              # 请求管理界面启用/修改保护
laodi pause request --duration 10m  # 请求有时限的例外；不能直接绕过授权
laodi undo <action-id>              # 有条件撤销本工具做过的动作
laodi uninstall                    # 走正式卸载；默认不删除未处理证据
```

`setup` 不能靠在可疑 Agent 中调用而自动获得系统权限。第一次可以让 Agent 引导下载与运行，但安装签名组件和授权由用户在可信系统界面完成；后续无需反复操作。

只有一个主 Skill：`skills/laodi/SKILL.md`。它负责识别“检查是否被打包”“保护当前项目”“解释告警”等意图，调用固定 CLI，展示原始结论与未知项，不自行解释任意日志或编造修复。

Skill 标准支持附带脚本，但它本身不提供 OS 隔离或持续监控。[S1] 不把 `allowed-tools` 当成系统安全授权。

Agent 默认只读接口返回：能力状态、证据类别计数、匿名 incident ID、本地管理动作引用、未知项。不返回完整路径、原始 manifest、remote、源码和凭据。真正敏感详情只在本地可信 UI/终端显式查看。

宿主 hooks 仅用于会话开始时检查 Guardian 是否在运行、一次性提示覆盖缺口、附加可选工具策略。必须按宿主版本测试字段、失败语义和用户信任流程；不能假定所有 Agent 的同名 hooks 行为相同。Hooks 不是主进程后台上传拦截器，不承担唯一安全控制。

不需要 MCP server：已有 CLI 足够完成只读交互，减少常驻端口和攻击面。只有真实客户端无法调用 CLI 时才重新评估。

## 14. 数据与状态契约

### 14.1 能力不是单个布尔值

```json
{
  "schema_version": 1,
  "capability": "filesystem_deny",
  "backend": "macos_es",
  "scope_id": "scope_local_01",
  "state": "active",
  "verified_at": "<actual-time>",
  "policy_revision": "p_12",
  "limitations": ["preexisting_open_handles_require_restart"]
}
```

状态为 `unavailable / needs_permission / initializing / active / degraded / disabled`。`active` 必须来自真实初始化与探针；后端退出、权限被撤回或测试失效时自动降级。

### 14.2 事件结构

```json
{
  "schema_version": 1,
  "event_id": "evt_local_01",
  "kind": "sensitive_manifest_match",
  "observed_at": "<actual-time>",
  "baseline_existing": false,
  "sensor": {"id": "client_a_snapshot", "version": "parser-revision"},
  "subject": {"app_id": "verified-or-unknown", "process_attribution": "unknown"},
  "facts": {"categories": ["git_objects"], "inspection": "completed"},
  "evidence_origin": "client_artifact",
  "delivery": {"attempted": false, "acknowledged": false},
  "unknowns": ["network_payload", "remote_retention"],
  "local_evidence_ref": "<not-in-agent-summary>"
}
```

本地 manifest 中的时间、路径、字段都是不受信输入；展示时转义终端控制字符和 HTML，不把它们作为命令、通知动作或任意文件读取路径。

### 14.3 事件生命周期

```text
观察 → 原始证据分类 → 有界解析 → 事实事件 → 去重/关联
                                           ↓
                                      本地 incident
                                           ↓
                                  通知尝试/送达结果
                                           ↓
                                用户查看/处置/保留未知
```

`acknowledged` 只表示用户确认看过，不表示风险消失。`mitigated` 必须带具体 action、范围与复查结果；“删除本地包”不能被解释成“远端删除”。

### 14.4 本地存储

用户级数据放本机应用数据目录，权限收紧，避开默认漫游目录。数据包含登记信息、脱敏事件、游标和动作恢复记录；不建立原项目镜像。

系统组件规则放受平台保护的配置位置，通过受验证管理通道更新。普通 Agent-summary 通道没有修改权限。管理变更采用 plan → 用户授权 → apply → verify → journal；撤销只恢复仍符合预条件的本工具变更，不覆盖用户之后的配置。

## 15. 自我保护与可靠性

- 同一用户只运行一个 Guardian；锁、IPC 和启动服务都具备实例身份及版本检查。
- 重启后恢复游标和事件，截断尾记录可识别，未知 schema 不猜测。
- 同进程控制策略文件、事件记录和管理 IPC 不向受限客户端开放；系统模式验证调用者签名和权限。
- watcher overflow 触发有界重扫与 degraded 状态；不能丢事件后仍显示持续完整监测。
- 休眠恢复、目录被移走、应用升级、代理变化都触发自检。
- 静默更新规则默认关闭；更新随签名发行包或用户显式检查完成，记录版本与来源。核心不默认联网、不上传遥测、不会把本地证据交给 LLM。
- 守护进程崩溃时由 OS service manager 恢复；原生执行组件保留有效策略，通知链恢复后报告覆盖中断区间。若组件行为不满足这一点，发布文案不得声称 fail-closed。
- 系统组件授权超时、规则编译失败、队列压力的行为必须有测试，不拿“系统级”三个字替代验证。
- 卸载时先解释哪些保护将移除；残留扩展、规则、launch item 和本地记录逐项可查看。没有未处理证据的明确授权，不把它们全部删掉。

## 16. 明确不进入首版的功能

- 仓库复制、三方合并、Review/Apply、Git 历史搬家。
- 任意 TLS 解密、全局根证书安装、全盘内容 DLP、自动判断商业秘密。
- 云后台、账号、团队看板、遥测、默认上传报告。
- 自研反恶意软件引擎、内核驱动、动态插件市场、万能客户端配置修改器。
- 自动停用系统安全保护、绕过 Apple entitlement、自动授予 Full Disk Access。
- 未经测试的跨平台支持，以及把 GUI 已存在实例误认作 launcher 子进程。

## 17. 方案取舍记录

| 方案 | 优点 | 拒绝/采用原因 |
|---|---|---|
| 纯 Skill＋提示词 | 安装感轻、Agent 入口自然 | 无法约束宿主后台，不能当核心 |
| 干净副本＋写回 | 降低附带历史、可放弃任务 | 每任务操作重，不能满足最新全面防护目标 |
| 将 `.git` 移到外部 | 保持原目录工作，减少浅层打包 | gitfile 可被跟随，无上传感知，不当保护核心 |
| 只看目录变化 | 可快速交付、低资源 | 会漏内存直传；仅作为 Preview 传感器 |
| 只管网络域名 | 能阻止未知目标 | 同域业务与外传难区分，TLS 正文不可见 |
| 全进程 launcher＋观察器 | 原目录、可验证的敏感读限制 | 采用为 Beta；不冒充任意 GUI 覆盖 |
| macOS ES＋NE＋共用核心 | 覆盖日常 GUI 启动，更接近一次安装 | 采用为正式 V1，接受授权与平台成本 |
| 全 TLS 内容审查 | 有机会做请求级策略 | 兼容、凭据、隐私和维护成本大，另立后续研究 |

决策驱动：真实执行优先于文案；日常操作成本优先于“内部零组件”；覆盖和未知同时可见；默认不增加另一条数据外传通道。

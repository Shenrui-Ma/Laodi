# 0.2.1 开放源码前检查

日期：2026-09-19。结论：保留现有架构，修复持续运行与可见性问题；不为首次公开增加新的后台服务、数据库或运行依赖。

## 当前结构

```text
cmd/laodi                         CLI、Hook入口与接入命令
internal/laodi/scanner.go          受支持版本的快照元数据检测
internal/laodi/hooks.go            工具事件归一化与本机输出检测
internal/laodi/hook_inbox.go       私有、脱敏、有界队列
internal/laodi/store.go            事件存储与分离的去重策略
internal/laodi/runner.go           单守护进程、消费与异步通知
internal/laodi/service.go          用户级后台安装
internal/laodi/hook_config.go      两个客户端的配置接入与归属管理
platform/macos/notifier            短命无窗口系统通知helper
skills/laodi                      按需查询、解释和接入引导
spikes/s0                        历史研究探针，不随产品启动
```

各输入先经受约束分类，再写脱敏记录；监测器持久化事件后确认队列消费。通知不在Agent工具执行的同步路径内。Skill不承担强制安全控制。现有规模不需要拆包到多个服务，也不需要引入数据库、代理或大模型判定。

## 本轮必要调整

1. **容量故障隔离。** 快照去重达到4096后，保留已知记录并继续追踪其变化，新增无法跟踪的快照明确降级。Hook检测继续，容量问题产生一次持久告警，避免后台反复启动失败。Hook仍独立保留最近2048个去重键。
2. **摘要说清观测对象。** 快照只读元数据；工具检测会在本机短暂检查输出。查询不再用同一条“没有检查内容”描述两者。
3. **文本查询显示通知状态。** 未配置、未授权、helper失败、系统接受及未知送达等可直接查看，不要求用户手动读JSON。
4. **统一公开入口。** README给出一条清楚的构建、Hook、监测和通知路径；“一次接入”不等于已经通过正式分发或实际通知验收。
5. **公开材料脱敏。** 不提交`.omx`、本地二进制、构建目录、私有日志/数据库。历史合成实验的可关联线程标识和随机临时目录名已脱敏，测量数值保留；PNG原图的附加元数据已检查，不含个人路径/提示词工作流。
6. **最低Go版本兼容。** 首次远端CI发现Go1.25的嵌套`os.Root.Name()`只保留相对名称，导致私有队列的Unix安全打开/锁定位失败。现显式绑定绝对目录并保留前后文件身份校验，补充最小版本回归；不能用本机较新工具链通过代替最低版本验证。

## 验证

本轮执行Go竞态测试、vet、构建和合成Hook全链路回放；公开仓库配置macOS CI，固定官方Actions提交版本并仅授予contents读权限。测试只用临时HOME、合成内容和假通知helper，不读取用户真实凭据，不发系统通知。

0.2.0及此前的资源和S0结果仍保留原构建身份，不能当作0.2.1新测量。合成实验的成功也不等于真实客户端回调、签名分发和长期运行已经全部通过。

## 保留的发布边界

- 当前是开发预览版，真实客户端回调、系统通知呈现、Developer ID签名/公证和长期稳定性待验收。
- 默认检测并告知，不自动拦截；纯内存直传、更多Agent后台路径属于后续TODO。
- `setup`、Hook接入和通知授权是不同步骤。空队列、不出现快照、系统接受通知都不能单独证明完整保护。
- 安装器使用精确归属和原子文件替换，但配置文件与收据并非跨文件事务；外部同时编辑配置仍有竞态。
- MIT覆盖原创代码/文档；用户提供的PNG素材另见[资产说明](../assets/README.md)。

旧[架构设计](ARCHITECTURE.md)、[V1取舍](PRODUCT-V1.md)和S0材料保留为决策历史。现在如何使用以README、[工具事件说明](TOOL-HOOKS.md)和代码为准。

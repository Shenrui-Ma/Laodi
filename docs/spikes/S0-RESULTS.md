# S0 技术验证结果

> 后续产品取舍已更新：用户不接受Git损失与长任务中断，因此当前V1以[PRODUCT-V1.md](../PRODUCT-V1.md)为准，采用非阻断监测。下文保留S0实验事实与当时的研究结论，不代表现在要默认启用严格阻断。

日期：2026-09-18。平台：macOS 26.3（25D2125）、arm64，SIP 保持开启。

## 当前结论

**OS 级限制在受测的完整合成客户端进程树中确实生效，但“封住 `.git`”不足以成为完整产品；完全封禁 `.git` 的当前策略无法保留原生 Git 工作流。** 正式 macOS 系统扩展的分发路线有官方依据，尚未取得账号/受限 entitlement，也没有实际安装系统扩展。这里没有比较其他权限设计，不能外推为任何方案都无法兼容 Git。

这轮结果可以支持继续做受限运行与监測原型，不能支持发布“所有 AI 工具都不会上传历史”的保证。

## 1. 环境与安全范围

- Apple Git 2.50.1、Python 3.13.13、Node 24.14.0、Apple Clang 17。
- 只生成临时合成仓库和明显无效的测试秘密；没有读取真实项目或用户凭据。
- 接收端仅绑定 127.0.0.1；合成标记没有发送到公网。
- 没有关闭 SIP、修改权限、安装扩展或后台服务。后续仅在临时目录下载了固定版本 sandbox-runtime 及依赖，跳过安装脚本；未增加全局或产品依赖。
- 使用 macOS 现有 Seatbelt/sandbox-exec。手写的是实验策略，不是计划中的 sandbox-runtime 产品集成。
- npm 最初没有走本机系统代理，镜像与官方 registry 均遭 ECONNRESET。只对下载命令显式指定已存在的本地代理后，从官方 registry 取得 0.0.76，记录 integrity 和依赖锁快照；没有改系统或 npm 持久配置。

## 2. 数据读取与端到端对照

可复跑脚本：[security_probe.py](../../spikes/s0/security_probe.py)
原始结果：[s0-security-results.json](s0-security-results.json)

共 42 场景：14 个正向对照、19 个限定范围的预防测试、9 个边界实验。**42/42 符合实验预期，包括有意展示的泄露，不是 42 项安全保证。** 独立审查后强化了网络阻断的“接收端确实为零字节”断言，并补齐 separate-git-dir 外部对象的直接读取对照。

历史标记先提交到 Git，再从当前工作树删除。无保护对照确实可以取出并发送给回环接收端；受保护组把整个 Python 客户端主进程放进 sandbox，再执行各类读取，而不是在代码里做路径字符串过滤。

| 检查 | 无保护对照 | 受保护观察 |
|---|---|---|
| `git show` 读取删除前的历史 | 标记到达接收端 | 无法读取、没有发送 |
| Python 解压 loose Git object | 可读可发送 | 打开文件被拒绝 |
| Python 子进程和独立 session 子进程 | 可读可发送 | 限制随进程树继续生效 |
| Node fs、C fopen | 可读可发送 | 读取失败，子进程错误保留 |
| symlink 指向受限对象 | 可读可发送 | 被拒绝 |
| 当前允许源码 | 可读可发送 | 仍然可读可发送 |
| 未批准的第二个回环端口 | 对照允许时能发送 | 端口受限后无法发送 |
| 离线模式 | 对照接收端可用 | 无法连接接收端 |

本地 Git 布局实验还验证了：只保护工作树里的 `.git` 路径，并不能挡住已知真实位置的 worktree/common-dir、alternates、separate-git-dir 对象；解析并拒绝真实对象根后，对应直接读取被阻止。单次 `git show` 因 gitfile 不可读失败，不足以证明真实对象库也已经不可读。

## 3. 实测暴露的边界

| 边界 | 本轮观察 | 对实现的要求 |
|---|---|---|
| 受限对象在其他位置的硬链接 | 标记仍到达接收端 | 不能把路径 deny 宣传成同内容全面隔离；生产策略需明确处理范围/拒绝条件 |
| 秘密预先放入环境变量 | 标记仍到达接收端 | 启动前最小环境；受限读取不能撤回已进入内存的数据 |
| 沙箱前已打开的文件描述符 | 标记仍到达接收端 | 关闭额外继承 FD；本轮关闭后的对照确实不能读取 |
| 允许访问已运行的代读 helper | helper 返回秘密，标记到达接收端 | 不能默认放行所有 localhost/IPC；只约束新进程不约束外部服务 |
| 禁止该 helper 端点 | 无法取得并发送标记 | 证明限制去向能补一部分代读路径，不代表所有 IPC 均覆盖 |

本轮的 helper 是合成 HTTP 服务，不是已经完成 ZCode/Electron 单实例验证。没有测试完整系统中任意硬链接发现、所有 FD 类型、mmap、Apple Events、Docker socket 或所有 IPC。

## 4. 普通开发功能损失

脚本：[compatibility_probe.py](../../spikes/s0/compatibility_probe.py)
原始结果：[s0-compatibility-results.json](s0-compatibility-results.json)

11 类操作 × 2 种模式 × 5 次，共 110 个独立样本，每个样本使用新的合成仓库。

| 操作 | 无保护 | 完全禁止读取/写入 `.git` |
|---|---:|---:|
| status、diff、log、show、add、commit | 30/30 成功 | 30/30 失败 |
| 当前源码读取/编辑 | 10/10 成功 | 10/10 成功 |
| Python unittest | 5/5 成功 | 5/5 成功 |
| Node 内置测试 | 5/5 成功 | 5/5 成功 |
| C 编译并执行 | 5/5 成功 | 5/5 成功 |

这意味着“原目录编辑和不依赖 Git 的基础测试”可保留，**不意味着完整日常开发兼容**。依赖 Git 自动生成版本号、复杂 framework 构建、IDE 索引、Git 插件和真实 AI 客户端任务仍需专项测试。

轻量成功操作的保护后中位耗时约增加 4.5–6.3ms（包括 sandbox-exec 启动）。C 编译样本受缓存影响反而变快，不能据此宣传性能提升。失败得更快的 Git 操作也不代表性能更好。

## 5. 真实 Codex CLI 与本地假 Provider

脚本：[real_cli_probe.py](../../spikes/s0/real_cli_probe.py)
结果：[s0-real-cli-results.json](s0-real-cli-results.json)
过程与限制：[S0-REAL-CLI.md](S0-REAL-CLI.md)

本机已有 Codex CLI 0.137.0 在新的 HOME/CODEX_HOME 中运行，不读用户配置/认证，外层拒绝真实用户家目录访问，只允许本地 stub 端口。stub 提供确定的 Responses 工具调用，不使用真实模型、付费 token 或第三方 API。

| 结果 | 无历史限制对照 | 禁读 `.git` |
|---|---|---|
| 客户端退出与工具闭环 | 退出 0，实际2次请求 | 退出 0，实际2次请求 |
| 当前源码读取、生成文件、简单断言 | 均成功 | 均成功 |
| `git show` 历史 | 成功 | 退出128 |
| 直接读取 Git 对象 | 成功 | PermissionError |
| 历史标记出现在回传 Provider 的请求中 | 是 | 否 |

第一次实验发现 Codex 仍采用 macOS 系统代理，NO_PROXY 并未阻止这一回退；因为外层没放行代理端口，stub 收到0请求，当时正确记录为实验未完成。随后为子进程明确设置所有代理变量指向同一个本地 stub，stub 只接受目标为自己的请求且不转发，新方案成功。未开放真实系统代理给受测客户端，也未修改系统代理。

这证明真实客户端在这次受限进程、合成任务和假 Provider 中的行为，不能替代 ZCode GUI、真实模型服务、旧实例及所有插件测试。

## 6. 固定版本 sandbox-runtime

脚本：[runtime_probe.py](../../spikes/s0/runtime_probe.py)
结果：[s0-runtime-results.json](s0-runtime-results.json)
依赖来源：[锁文件快照](s0-runtime-package-lock.json)

从官方 npm registry 临时取得 `@anthropic-ai/sandbox-runtime@0.0.76`，跳过 install scripts。10项对照全部符合预期：历史读取、语言原生对象读取和子进程读取被拒绝；当前源码经 runtime 的受控代理成功发送；未批准端口由代理返回403；绕过代理直接连本地接收端被 OS 拒绝。拒绝结论要求接收端确实没有收到字节；子进程场景有对应正对照并核对目标路径的权限错误。

这组测试使用合成 Python 客户端，网络是回环 HTTP，没有测试公网 DNS、TLS 或生产 profile。锁文件是此次安装的来源快照，部分路径包含临时目录，不能直接当作可移植的产品 npm-ci 清单。

随后将同一固定版本 backend 与真实 Codex CLI 联合运行，结果见 [s0-real-cli-runtime-results.json](s0-real-cli-runtime-results.json)。两组同样完整执行任务：对照的历史秘密到达本地 stub，受限组没有；普通读写和简单断言保留。CLI 的 Git 和直接对象读取两条路径分别断言，并验证 stub 本身没有错误，不能用一条路径的成功掩盖另一条失败。

联合验证第一轮发现 runtime 注入的 NO_PROXY 把回环模型 URL 排除在代理之外，导致直连被正确拒绝。只在受限命令入口清空 NO_PROXY/no_proxy，使请求通过 runtime 的严格白名单代理后成功；没有放宽实际网络规则。这是客户端 profile 必须处理的代理兼容性，不应建议用户通过全开 localhost 解决。

实际发现一个适配问题：默认 macOS 临时目录加上隔离 HOME 和 mux socket 文件名达到107字符，AF_UNIX bind失败；同样结构放到 `/private/tmp` 下后为63字符并能创建。生产 launcher 必须给 runtime 分配短、私有、有界的 socket 目录，不能仅把随机长路径拼起来。

## 7. 本地监测可行性

脚本：[watcher_probe.py](../../spikes/s0/watcher_probe.py)
结果：[s0-watcher-results.json](s0-watcher-results.json)

Python 标准库 kqueue 的目录＋文件 vnode 监听完成四类测试：20/20小型完整 manifest 检出；半JSON不提前报，原地追加完成后检出；目录重命名触发配置路径失效；启动前已有文件进入基线且不报成新事件。

空闲同步事件泵中的本地检测 p95为0.134ms，仅从原子发布/追加完成计时到内存事件产生，不包含真实应用语义、负载、系统通知或网络上传时间。这个数字不能作为产品实时通知SLA。

只监听目录不足以可靠获知已有文件继续追加。本探针为观察文件逐个持有FD，峰值22个；规模化预算、重挂载、休眠恢复和漏事件恢复仍未完成。系统通知未请求权限、未弹窗、未验证送达。

## 8. 正式 macOS 分发与授权

完整核验与申请材料见 [S0-MACOS-DISTRIBUTION.md](S0-MACOS-DISTRIBUTION.md)。

- Developer ID 签名、公证、宿主内嵌 ES/NE system extensions 的正式路线存在。
- ES 需要 Apple 单独批准受限 entitlement；账号付费本身不等于获批。
- 用户随后需要通过系统界面批准扩展、Full Disk Access、网络过滤与通知。
- 当前只有 CLT/SDK/公证工具可用的只读检查；没有确认付费账号、证书、profile，也没有申请或实测系统扩展。
- 当前没有必要让用户先购买会员。下一步先确认关键技术与产品取舍，再准备正式资格。

## 10. 工程决策

1. **有条件继续**：原目录的整进程树限制可以作为 Beta 的技术基础。
2. **不直接开始全面产品宣传**：当前手写路径策略不是生产后端，更没有跨应用全覆盖。
3. **先处理已证明的入口问题**：环境、额外 FD、真实 Git 根和 IPC 例外都应在启动前收敛，不在 Agent 开始运行后补救。
4. **产品定位须接受 Git 损失**：若“Agent 完整 Git 功能照常”是必须项，需要额外设计并验证受控查询路径；不能直接把 Git 可执行文件放进白名单。
5. **正式系统版是独立验证阶段**：没有 Apple 授权与真实客户端测试之前，保留 NOT VERIFIED 状态。

本轮没有运行完整 76 项产品验收矩阵；这些是 S0 探针样本。后续测试报告应按矩阵逐项映射，不能相加计数后声称产品验收完成。

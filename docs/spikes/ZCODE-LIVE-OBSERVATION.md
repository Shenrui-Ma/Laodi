# ZCode 登录后的只读观察与产品修正

观察日期：2026-09-18。用户报告已登录BigModel、在默认工作区对话，随后打开自己指定的仓库并要求查看最近提交。本轮用户明确授权对照相关对话和后台信息。

## 检查范围

- 读取已安装App的构建号，仍为`3.12.3.7463`。
- 只读检查默认checkpoint/旧snapshot目录的存在性和已知元数据。
- SQLite用`mode=ro`＋`query_only`，只选默认工作区和用户指定项目的相关会话，提取工具名称、输入命令类别、完成/审批状态，以及输出长度。
- 针对用户已经贴出的提交片段，在对应模型I/O记录中本地计算是否出现；不输出请求头、聊天正文、环境变量值或秘密。
- 后台日志只提取事件类别和计数；网络只检查瞬时连接元数据，不抓载荷。
- 没有读取私钥、配置本体、业务源码或Git对象；没有改代理、权限、ZCode配置，没有中止任务。

原始定位与脱敏中间材料只保存在被忽略的私有`.omx/`目录，没有复制真实会话日志进仓库或测试fixtures。

客户端自己的上下文快照已经包含仓库元数据。模型工具审批和客户端自动附加上下文、后台采集需要分别解释；模型回复中的一句权限保证不能代替宿主行为验证。

## 代理状态

用户报告为使用ZCode调整过代理。只读观察时，macOS系统代理旗标仍为启用；该时刻ZCode进程树未见连往已配置本地代理端口的连接。应用自己的设置、系统代理开关、代理程序的模式与瞬时连接不是同一个观测量。

本轮没有改变任何代理设置，也不据此判断过去请求一定直连或经过代理。产品不能为了“检测”强迫修改代理，不能把一个网络目标/代理连接直接称为泄露。

## 已落实到0.1.1-dev的改进

1. **正常工具使用不报警。** 用户要求的代码阅读、git log和宿主常规仓库上下文不作为整仓外传证据。
2. **无Git工作区也能覆盖附加清单。** 新增extra-manifest的global-configs元数据解析，不读取配置文件本体。
3. **额外配置阶段独立关联。** 分别处理nextExtraManifestHash与lastAcceptedExtraManifestHash，active/pending别名去重，不能用新pending冒充accepted。
4. **摘要与通知不输出配置细节。** 只保留global_config_paths数量；文件名、source、contentHash、配置值不进入Agent摘要或通知。
5. **词面匹配不等于事实。** 相关配置字段出现在普通日志里不能生成snapshot事件；缺少证据目录也不能显示“没有上传”。

新增事件：`global_config_manifest_match`、`global_config_upload_attempt_recorded`、`global_config_upload_acceptance_recorded`。通知仍异步、限频、不要求用户暂停任务。当前真实环境没有可供端到端复现的extra清单，所以解析正确性仍由已核对代码契约＋合成回归证明，不冒充真实上传复现。

## 产品范围仍然克制

本次会话核查是用户明确要求的一次性取证，不将其变成默认翻阅聊天日志、环境输出或全部项目的功能。Laodi继续只默认观察已支持的快照元数据，不封Git、不更改Agent权限、不调整网络、不阻断长任务。

下一次真实检测验证应使用已准备的合成仓库和独立测试数据环境。没有必要让模型读取真实密钥来“证明能读”；只看到私钥文件名也不是轮换密钥或宣布泄露的充分证据。

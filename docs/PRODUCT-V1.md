# Laodi V1：不打断开发的本地隐私哨兵

> 历史决策记录：本文描述0.4阶段的V1取舍。0.2.x开发实现已增加可选的本机工具输出检查；当前安装方式和架构以[README](../README.md)、[工具检测说明](TOOL-HOOKS.md)和[发布检查](RELEASE-REVIEW.md)为准。本文的“首发只看快照”等表述不代表当前全部能力。

决策日期：2026-09-18；版本0.4；本文件优先于0.3架构中的首发范围与路线。依据：用户最新明确要求不影响Git、不阻挠长任务、无GUI、轻量、用途一眼可懂，以及本地保存的 S0 研究记录。

## 1. 一句话定义

**给 AI 编程工具加一个本地隐私报警器：盯住已支持的仓库打包和上传线索，有异常及时告诉你。**

主口号：**AI 安心写，老底替你盯。**

名称固定为Laodi；Skill帮助安装、查询、解释，独立用户级进程负责监测。不借模型判断是否存在泄露，不需要另开一个客户端界面。

首发先做好某APP的经过验证的快照线索闭环，不在README宣称支持全部AI产品的所有上传。正常Git命令、编译、模型请求本身不产生风险警报。

## 2. 最新优先级与不能同时承诺的事情

硬约束：

1. 不改变用户的Git/SCM使用方式。
2. 不暂停、取消、重启、拒绝Agent正在执行的任务。
3. 不引入专用GUI、仪表盘、常驻网页、系统扩展作为首发前提。
4. 以普通用户身份运行，按需访问已选择的数据目录。
5. 覆盖内有异常及时记录和通知，失效可见。

“尽可能避免额外外传”继续作为目标，但不能把它解释为默认全面阻断。**无同步拦截、无内容检查、永不打断，与保证所有外传事前被阻止并不相容。** 当前选择保留工作流，先交付可信监测；内存直传、未知客户端格式、没有可观测落盘的行为仍可能漏检，必须在支持范围里说明。

后续只接受经真实客户端验证、针对独立后台采集路径的缓解措施；如会影响正常任务、回滚、索引等功能，必须说明并由用户在任务结束后选择。没有无副作用证据，就不提供“自动修复”。

0.3的整`.git`禁读、网络白名单、ES/NE系统防护和严格启动器留在研究材料，不是V1默认流程，也不是V1发布前提。

## 3. 权限

| 项目 | V1要求 |
|---|---|
| 管理员/root | 默认不需要，不用sudo启动Guardian |
| Agent Full access | 不是依赖；只影响Agent能否执行安装/查询命令 |
| 普通文件权限 | 监测当前用户可访问的已知应用数据目录 |
| macOS隐私目录权限 | 遇到TCC受限目录时按需引导；不能继承另一个App的授权承诺 |
| Full Disk Access | 不作为默认安装要求；不可读时报告该范围未覆盖，先评估更小授权 |
| 通知许可 | 系统通知需要用户一次选择，之后持续检查许可状态 |
| ES entitlement/系统扩展 | V1不需要，不要求用户为此先购买开发者会员 |

Codex Full access取消的是Codex自身的本地沙盒/审批限制，不会自动成为root、FDA或Apple受限entitlement。[R1] 以root运行Agent也不会让普通Skill变成网络监控器，反而扩大Agent本身的权限。

Guardian由用户级服务管理器启动，脱离具体Agent会话。Agent退出或没有调用Skill，不影响已经运行的监测。安装在一个当前权限不足的Agent里时，只让用户在自己的可信终端完成必要步骤，不要求扩大Agent全部权限。

## 4. 默认模式绝不进入任务的同步阻断路径

V1没有PreToolUse拒绝逻辑，没有网络中间人，没有每条命令的确认弹窗，不改变Codex权限配置。

发现异常时：写入本地事件→去重→发送系统通知。当前任务继续。Agent不能因为看到摘要就自行取消任务、卸载客户端、清理证据或修改网络配置；用户明确请求处置后才执行对应流程。

首版不向进行中的Agent会话主动注入警告提示词，避免模型自行改变任务计划。用户主动询问时Skill读取摘要；经过宿主验证后，可以在任务结束时补充一条非阻塞摘要。核心检测不能依赖这条摘要。

用户让Codex执行长任务并打开Full access时，Laodi仍只观察已支持的证据目录。不拒绝git，不关网络，不杀进程，不替用户降级权限。

## 5. 用户怎么收到提示

主通道：**非模态系统通知**，不抢焦点，不要求点按钮后任务才能继续。不是模态警告框。

补充通道：本地可回看的事件记录；用户在Agent里问“老底刚才发现了什么”，或执行`laodi incidents`。通知被关闭、Focus屏蔽或用户离线时，不能保证用户立即看到，需保留事件并明确通知不可用。

macOS可使用很小的无窗口通知helper，通过系统通知API建立稳定身份；可以采用LSUIElement后台bundle，不做主窗口、Dashboard或常驻菜单栏。[R2][R3] 打包、签名和首次通知权限体验要单独验收，不靠冒用其他App身份规避权限。

通知示例：

```text
发现：Git 历史打包
某APP的打包清单包含 Git 历史，上传情况待确认。
```

只在已验证的客户端状态语义支持时，才显示“客户端记录表明上传已被接受”。不把清单、尝试、成功、远端保存混为一谈。

默认不显示仓库名、文件路径、秘密正文。首次扫描发现旧记录标“安装前已有”；重复事件聚合，重要状态升级再提醒；不要每个Git读取或每次模型连接都打扰用户。

## 6. 最小架构

```text
Agent Skill / laodi CLI
           │ 只读脱敏查询
           ▼
一个用户级Guardian
  ├─ 有界数据目录监听
  ├─ 某APP已验证版本解析器
  ├─ 事件分类与去重
  ├─ 本地有界记录
  └─ 系统通知适配（必要时短时启动无窗口helper）
```

核心维持Go；无需常驻Node、模型、浏览器、MCP服务或HTTP管理端口。S0中的Python和sandbox-runtime是研究探针，不随V1监测版常驻。

与0.3相比，V1不创建`platform/macos/FileGuardExtension`、`NetworkGuardExtension`、PolicyAuthority等实现。保持单主要Skill，不拆成一堆记不住的入口。

用户只需：一次setup，平时无操作，有提示时查询详情。命令建议维持`setup/status/check/incidents/doctor/uninstall`，不为宣传增加同义别名。

## 7. 资源与故障预算

成品目标而非实测承诺：Guardian稳定空闲RSS≤50MiB，平均CPU≤0.2%；默认事件存储≤50MiB；通知helper有独立峰值预算，不把它排除后声称整套产品都在同一预算内。

目标资源使用靠以下约束实现：

- 只监听已知数据目录，按变化读取小型清单和状态。
- 不扫描全盘、不解压`.enc`、不复制源码、不全量扫描Git对象。
- 清单流式或有上限解析，队列有界、记录轮转。
- 原型的每文件一个FD不是生产默认；监测数量超限时受限重扫/重试并显示降级，不改变用户系统limits。
- 异常风暴合并、限速；检查失败不影响Agent，Guardian自己降级并告知。

S0 原型与 Go 成品须分别测量。资源探针输出保存在本地 `.omx/experiments/`，短时合成负载不能替代长期 CPU、稳定性和通知辅助进程测量。Go 开发版使用有界元数据巡检和解析缓存，不为每份清单长持文件描述符。

## 8. 某APP专项验证是首发门槛

**必须做。** Codex上的沙箱实验不能替代某APP的文件格式、后台行为和体验验证。

条件：使用干净测试用户或隔离虚拟机，记录某APP准确版本与安装包身份；只用合成仓库/假密钥，不打开用户真实项目。需要登录时用专门测试账号，并由用户完成登录，不复用现有私人会话。

测试分为两组：

1. **原始行为取证**：当前正式版本实际产生哪些清单/状态，何时更新；官方开关是否有效。旧版本若合法可得且有测试价值则单列，不能把旧行为推广到最新版。
2. **Laodi有/无对照**：相同任务检查任务结束状态、Git功能、输出文件、退出码、网络错误、额外耗时，以及告警事实是否准确。

最小任务矩阵：

- 正常对话、代码编辑、git status/diff/commit和普通测试。
- 一个有历史假秘密、当前文件已删除的合成仓库。
- 长任务运行期间出现快照变化：任务不被取消、不出现Laodi引入的权限/网络错误。
- 正常模型上下文、普通Git操作不得被当成整仓泄露。
- 默认/相关官方开关各状态、应用重启、升级后的未知schema。
- 旧记录不报为新上传；pending/失败/accepted语义分别与实际观察核对。
- 通知关闭、Focus、同一记录反复更新、目录不可读时的退化表现。

若当前某APP不再产生旧快照机制，应正常报告“未发现该已知线索/当前格式不适用”，不制造警报来证明产品有用。此时再评估是否有值得维护的其他真实线索。

本机观察记录单独保留在本地；专项主动上传对照只使用合成测试环境。

## 9. V1发布门槛

- 对至少一个明确某APP版本验证来源字段与事件分类。
- 在有/无Laodi两组中，Git与正常任务均完成，长任务不被Laodi中断。
- 系统通知与本地记录可用；权限不足/通知关闭/解析器失效有准确状态。
- 无默认联网遥测、无源码上传、无全盘扫描。
- 按明确场景测RSS/CPU/FD/事件容量；72小时稳定性与升级恢复另行实测，不用短测替代。
- 首页明确已支持的采集证据范围；不使用“全面防偷”“所有上传都能及时发现”。

## 10. 来源与取舍

- [R1 OpenAI Sandbox](https://learn.chatgpt.com/docs/sandboxing)：Full access与本地沙盒/审批的关系。
- [R2 Apple LSUIElement](https://developer.apple.com/documentation/bundleresources/information-property-list/lsuielement)：无Dock界面的后台应用身份。
- [R3 Apple通知授权](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications)：通知权限与设置。
- [R4 Apple文件隐私访问](https://support.apple.com/en-gb/guide/security/secddd1d86a6/web)：文件权限/TCC边界。
- S0 研究记录保留在本地；整 `.git` 封禁的功能损失及读取限制边界须独立验证。

这次收敛明确优先保护开发流程。全面系统阻断仍有研究价值，但不再用它拖住一个小型、明确、低打扰的V1。

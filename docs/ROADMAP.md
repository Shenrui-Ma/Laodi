# Laodi-skills 开发路线与立项判断

> 当前优先级已由[PRODUCT-V1.md](PRODUCT-V1.md)更新：先实现不打断开发的ZCode专项监测、通知、脱敏Skill和真实兼容性测试。以下S2/S3保留为历史研究路线，不再是V1默认功能或发布前提。

状态：设计与实施计划；已完成一轮有范围的 [S0实验](spikes/S0-RESULTS.md)。当前没有可安装防护产品，不应执行本文拟定安装命令。

## 1. 总判断

用户最新目标要求预防与持续告警，意味着产品应接受必要的常驻进程和平台执行组件。继续坚持“零后台、纯 Skill、所有客户端全覆盖”会得到不诚实的承诺。

建议：**热点 Preview 与正式系统防护并行推进，能力严格分开。** Preview 提供立即可感知的已知线索检查；真正满足“装一次、原目录照常使用”的路线是 macOS 系统组件。Apple 能力审批是外部依赖，不能靠增加 Agent 数量消除。

## 2. S0：先验证能不能守住边界

产物归属：`backends/`、`platform/macos/` 的实验分支与 `docs/spikes/` 记录，尚不发布正式保护。

任务：

1. 确认 Apple Developer 签名/entitlement 路径、系统扩展安装授权及可分发条件。申请由用户控制的开发者账号完成，不擅自代签协议。
2. 在合成项目中验证 sandbox runtime 包装整个 CLI 主进程，可以拒绝 Git 历史读取、允许当前文件和正常模型目标。
3. 测现有桌面实例转交、helper、Git 子进程、worktree/alternates 等绕过路径。
4. 用虚拟客户端和测试接收端跑正反对照；建立 watcher 与通知健康探针。
5. 定义支持矩阵，不把理论上可用的 backend 直接标成正式支持。

退出条件：关键阻断机制至少一条经端到端验证；Apple 路径已明确可行性/阻碍。若所有实质阻断路线失败，项目只能定位监测工具，必须回来调整产品承诺。

不要先花两天做徽章、Logo、八个 Skill 或完整文档站。一个合成演示和准确首屏足够。

## 3. S1：可发布的热点 Preview

文件职责：`internal/evidence`、`adapters/zcode`、`guardian`、`notify`、`store`、`skills/laodi`。

实现顺序：

1. 先定 event/capability/agent-summary schema 与合成 fixtures。
2. 完成只读 `check`，把本地快照、尝试、接受记录分开。
3. 加 targeted watcher、去重、游标恢复和未知 schema 降级。
4. 加通知与服务安装、自检、卸载；无全盘扫描、无遥测。
5. 加一个薄 Skill，只消费脱敏程序结果；安装文案不承诺保护宿主已发生的数据行为。
6. 做一条真实运行的合成演示，发布明确能力矩阵。

发布门槛：VERIFICATION 中 O01–O18、适用 A 测试、资源/通知基本门槛通过。

**这是一份有用的监测试用版，不等于用户最终要求已经完成。** 不能把发布成功或 Stars 增长当成停止后续防护建设的依据。

## 4. S2：原目录 CLI 防护 Beta

文件职责：`inventory`、`policy`、`backends/sandboxruntime`、`app/run`、`tests/fake-client`。

实现：最小客户端 profile、Git 真根解析、环境/FD 收敛、出站规则、进程身份追踪、后端探针与失效提示。不要实现任意 Git broker。

用户入口可以是一个稳定的 `laodi run` 命令或独立快捷方式；提供可选一次性入口配置，但不覆盖原命令、不拦截未知 shell alias。

发布门槛：适用 L/N 测试完整通过，至少一个 CLI 版本完成代表性任务。存在未受保护的既有进程时，必须明确标出而非吞掉错误。

这一阶段比旧副本方案少了复制、依赖重装和 Apply，但仍需要受保护入口；不能宣传为任意桌面启动自动受控。

## 5. S3：macOS 系统防护 V1

文件职责：`platform/macos/HostApp`、`FileGuardExtension`、`NetworkGuardExtension`、`SharedProtocol`、`Packaging`。

先做文件访问授权，再做连接控制；二者使用共用 policy revision 与能力状态。分别运行后再测试关联，不将热路径同步依赖 Guardian。

必须具备：

- 在正常系统安全设置下完成签名、公证、授权、安装、升级和卸载。
- 正确覆盖登记应用的主进程/helper/子进程及普通启动方式。
- Git 兼容性限制与敏感路径例外有明确产品解释。
- 未授权连接处理、已有连接隔离结果和 TLS 内容盲区有准确状态。
- 权限撤销、缓存失效、系统 deadline、重启和资源压力都有测试。
- 管理请求与只读 Agent 查询严格分开。

发布门槛：适用 M/O/N/A 测试通过；至少一个目标桌面应用版本通过正反端到端测试；正式安装流程经真实目标用户完成。

**这是本文声明覆盖范围内的首个平台正式交付。** 允许源码经允许目标传输等盲区仍然存在，不能说所有外传均会阻止或告警。如果 entitlement 延迟，只延后系统版，不降低标准、不引导普通用户关闭 SIP。

## 6. S4：按真实缺口扩展

优先次序取决于数据：

- 第二个高频客户端的精确兼容 profile。
- Linux 更完整的系统事件能力；评估权限和 kernel 差异后再承诺。
- Windows 正式控制后端及签名、管理员授权、文件/网络规则测试。
- 用户确需的有限 Git 查询代理。
- 请求明文最小化 gateway：独立威胁模型，不能与域名过滤混称；默认仍不做全局 TLS MITM。

不主动增加云端团队控制台、报告上传或遥测。用户主动提供 fixture 时先本地脱敏。

## 7. 工作量与排期的诚实表达

下面是熟悉 Go 与桌面系统开发的小团队的粗估，用于区分数量级，不是交付承诺：

| 阶段 | 数量级 | 最大不确定性 |
|---|---|---|
| S0 技术探针 | 数个工程日 | 真实客户端隔离兼容性、Apple 分发前提 |
| S1 有质量的 Preview | 约一周上下 | 本地格式验证、通知与升级恢复 |
| S2 CLI Beta | 数周以内的独立迭代 | IPC/环境边界与后端回归 |
| S3 macOS 系统防护 | 数周至更长，外部审批另计 | entitlement、身份归因、授权时限、签名和实际兼容性 |

只有一个开发者且不熟悉原生系统扩展时，S3 不能套用最短估计。AI 可以加速代码和测试编写，但不能替代系统许可、长期压力测试或真实设备兼容性。

依赖管理策略：先设计并验证，再逐项引入；本次交付没有安装新依赖。系统扩展不可避免的平台代码与可选 sandbox 后端是有理由的成本；不再额外引入 Web 前端、数据库和运行模型。

## 8. 发布与传播

首屏应写当前发行版能力，不把架构目标列为已支持功能。目录可叫 Laodi-skills，发布标题按真实阶段区分：

- Preview：本地检查与持续提醒 AI 工具的已知快照行为。
- CLI Beta：原目录中的敏感文件读取限制与异常告警。
- macOS V1：对登记应用提供系统级敏感访问和连接控制。

演示只展示合成样本中的实测结果；可以引用事件背景，但不要借新闻省掉能力限定。

第一批用户验证三个问题：

1. 看首屏后能否正确理解何处阻断、何处仅监测？
2. 完成一次接入后是否能继续日常开发，而不反复关闭保护？
3. 收到警报时能否知道发生了什么、哪些仍未知、下一步怎么做？

正常工作流频繁触发例外时，先改善策略与支持范围，不默认大开白名单以降低投诉。

## 9. 预演失败与对策

| 失败情景 | 早期信号 | 应对 |
|---|---|---|
| 只有 watcher，用户以为任何上传都会被发现 | 安装页全部绿灯、没有能力矩阵 | 阻止发布文案，明确 Preview；系统路线继续 |
| Git 被限制后用户立即停用 | 高频 `git show/diff` 失败、反复请求全放行 | 缩小首批任务/客户端，解释取舍；有限 broker 后置验证 |
| 原生授权拿不到或需要高风险系统设置 | 无正式签名/要求关 SIP 才跑 | 系统版本暂停发布，保留明确边界的 Beta |
| 大量正常外联误报 | npm/索引/模型同域造成通知风暴 | 区分进程、目的、一次授权和聚合；不称有上传就有泄露 |
| 更新后 parser 失效却继续报安全 | schema 未知仍返回 completed | 强制 degraded，保留只确认的事实 |
| 保护组件自己泄露证据 | Agent 输出含完整路径/清单 | 白名单 schema 测试与默认本地详情 |

## 10. 实施团队分工建议

无需启动 OMX team 才能开始；以下是实施时可并行的边界，不是本次已经执行的工作：

- 核心执行者：`guardian/evidence/store`，维护公共 schema；负责 Preview 闭环。
- 平台执行者：`platform/macos`，先跑 entitlement/安装与热路径探针；不修改公共 schema，变更先协商。
- 隔离执行者：`backends/inventory/policy`，负责 launcher 与绕过测试。
- 测试/审查者：`tests`、支持矩阵、发布证据，独立验证能力声明。

Skill 与 README 在稳定 CLI 输出后再接入，不分配一条独立“提示词架构”主线。并行价值在平台探针与通用观察器，而不是同时实现三套相似安全核心。

## 11. 本次交付边界

已完成：产品定位、系统架构、仓库布局、接口草案、测试矩阵、发布门槛及风险记录；另已完成native和固定sandbox-runtime的合成实验、真实Codex＋本地stub对照、普通开发损失及本地watcher探针。

尚未完成：正式核心程序、Skill 安装包、系统扩展、Apple 授权、真实ZCode GUI和厂商模型兼容性、用户设备上的持久保护。

本轮没有修改用户的 ZCode、系统代理、防火墙、权限、真实Git仓库或后台服务。继续开发前应采纳S0发现的Git功能损失、继承FD/环境/IPC边界和代理兼容性；正式系统授权仍待外部条件，不能直接宣布项目能全面防上传。

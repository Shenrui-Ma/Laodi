# Git 历史打包（BETA）

`protect` 是可选功能。默认安装仍只监测；不会关闭正在运行的客户端。

```sh
laodi protect enable --dry-run
laodi protect enable
laodi protect status --format agent-summary
laodi protect disable
```

首次启用和撤销前需要正常退出客户端。启用后，普通启动方式不变；权限限制保存在文件系统中，不依赖额外常驻进程。更新老底会保留限制和恢复记录，卸载前必须先撤销。

## 支持范围

当前适配器只接受已核验的 macOS 客户端构建，并校验整个应用归档的 SHA-256。身份不同就拒绝启用。只处理当前用户默认缓存中的额外归档目录，不改项目 `.git`、网络配置、证书或客户端程序。

- 新工作区目录继承限制，阻止创建额外快照子目录。
- 已有归档目录不能新增包；已有待传包禁止读取内容，元数据仍可读取。
- 普通 Git 和同级检查点 JSON 不受这组权限规则限制。
- `status` 检查规则是否仍存在，**不统计实际阻断次数**，也不把没有新快照当成阻断证据。

客户端可能先读取工作区和全局配置，再因归档权限而失败。因此，这项功能限制特定归档流程，不能保证客户端没有读到内容。已经上传的内容也不会被撤回。

验证范围：固定原始归档代码与本地独立接收端的组件实验中，完整保护 9/9 次出现系统拒绝、目标接收为 0；普通 Git 与 checkpoint 检查 27/27 通过。数据和服务端输入为合成环境，Git、归档、加密与权限操作执行真实逻辑。另有 Python、Node、Shell 三种合成发送程序验证同一路径上的限制，保护阶段 18/18 次拒绝，撤销后恢复。它们不是三个真实产品，其他缓存路径不会自动受保护。

真实客户端已有正常任务与风险通知验证，但仍未取得完整原版客户端对官方服务的归档阳性与阻断对照，不能将“没有新包”当成完整事故复现成功。当前以 BETA 功能提供。

工具读取、正常模型上下文、纯内存直传、其他上传路径不在阻断范围。ACL 对同一用户的所有进程生效；同用户程序可以移除 ACL，刻意导入目录、符号链接或换数据根也可能绕过。它不是完整进程沙箱。

## 状态与恢复

后台监测运行时，每分钟检查一次已启用的限制。客户端变化、目录权限或布局异常会产生脱敏记录和限频通知，当前任务继续运行。通知是否显示仍取决于系统授权。

| 状态 | 含义与处理 |
| --- | --- |
| `disabled` | 没有老底的启用记录 |
| `enabled` | 当前客户端身份和目录限制检查通过 |
| `unsupported_client` | 客户端已变化，已有规则保留；当前版本效果未经验证 |
| `degraded` / `unknown` | 无法确认限制完整，不能当成已受保护 |
| `recovery_needed` | 权限变更未完成，保持客户端退出后执行 `protect disable` |

恢复记录位于老底状态目录下的 `archive-guard`，仅记录目录身份和 ACL，不保存源码或凭据。不要删除它，也不要用 `chmod -RN` 清除整棵目录的权限。老底只撤销能明确归属自己的条目；若目录被替换或 ACL 被其他程序修改，会保留恢复记录并报错。

正常启用/撤销需要短暂退出客户端，避免已打开的归档文件或正在发生的写入跨过权限变更。老底不会强制退出或重启客户端。
